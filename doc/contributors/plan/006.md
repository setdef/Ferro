# Plan 006: Bind idna

Tokra's notification plugin checks an attachment's URL the way Tauri's
url crate does, and the domain part of that check is idna's: UTS 46
mapping, normalization, Punycode, and the ASCII deny list. Ruby has no
UTS 46 tables, so Tokra's plan 024, decision 6 records a deviation: a
domain with non-ASCII characters, or a label starting with `xn--`, passes
unchecked. This plan adds `ferro-idna` 0.1.0.pre.1, which binds idna
1.1.0, the latest release (crates.io, published 2025-08-21; the
servo/rust-url repository, which has no `idna-v1.1.0` tag, holds its
source in `idna/`). [Plan 005](005.md) binds url, which depends on idna;
[ADR 001](../adr/001.md) and plans [001](001.md) to [004](004.md) hold
the rules and lessons this plan follows.

## One gem or two

ADR 001 binds one crate per gem, and url and idna are two crates: url
depends on idna (`url-2.5.8/Cargo.toml`, `[dependencies.idna]`) but does
not re-export it, so `url::idna` does not exist and a Ruby `Ferro::Url`
that held idna's API would invent a path the crate lacks. So idna gets its
own gem, and ferro-url links its own copy, as every Rust program that uses
both crates does through one copy.

Two copies in one process are harmless. ADR 001's danger is state the
operating system keeps once per process, and idna keeps none: `Uts46` is a
`const fn` over `idna_adapter::Adapter::new()` (`src/uts46.rs:500-508`),
which reads ICU4X's compiled data, immutable statics in each extension's
own private symbols. Nothing registers a class, a handler, or a file. The
cost is memory: each extension carries its own copy of the normalization
and property tables (measured in Results). The two copies could disagree
only if the gems locked different idna versions, so ferro-url's
`test_gem.rb` fails when its lockfile's idna differs from ferro-idna's.

## Design decisions

1. **Naming.** The gem is `ferro-idna`, `require "ferro/idna"`, module
   `Ferro::Idna`, extension `ferro_idna`. Rust's modules become Ruby
   modules, as plan 004 made `hotkey` into `Hotkey`: `idna::uts46` is
   `Ferro::Idna::Uts46` and `idna::uts46::Uts46` is
   `Ferro::Idna::Uts46::Uts46`; `idna::punycode` is
   `Ferro::Idna::Punycode`. The crate-level `Idna` struct is
   `Ferro::Idna::Idna`.
2. **Cargo features.** idna's three are its defaults and all are built.
   `compiled_data` must be on (`src/lib.rs:45-49` refuses to compile
   without it).
3. **Errors.** `Errors` carries nothing and prints its `Debug` text,
   `Errors` (`src/lib.rs:80-84`), so `Errors < StandardError` has that
   message, which a Rust test pins. A panic inside idna raises `Errors`
   too, with `idna panicked: <message>`, as ferro-global-hotkey raises its
   crate's base error (plan 004, decision 7): idna has no other error
   type.
4. **Bytes in, text out.** The functions that take `&[u8]` or
   `Cow<[u8]>` take a String's bytes, whatever its encoding, so input
   that is not UTF-8 reaches idna, which treats it as an error
   (`src/uts46.rs:517-519`). The `&str` functions take UTF-8 text and
   raise `EncodingError` otherwise, as magnus converts. Every result is a
   UTF-8 String. `domain_to_ascii_cow` and `domain_to_ascii_from_cow`
   differ only in Rust's borrowing, so both exist and behave the same.
5. **Tuples with a `Result` inside.** `domain_to_unicode`, `to_unicode`,
   `to_user_interface`, and the deprecated `Config#to_unicode` return a
   pair whose second item is a `Result<(), Errors>`. Raising would lose
   the first item, which the crate keeps on purpose: it marks errors with
   U+FFFD for a person to read. So Ruby returns a two-element Array,
   `[text, nil]` for `Ok(())` and `[text, Errors]` with an unraised
   `Errors` for `Err`. The RDoc carries idna's warning that the text must
   not be used in a network protocol when the second item is an error.
6. **`char`.** Ruby has no character type; a character is a String of
   one, as `String#chars` returns. `Punycode.decode` returns an Array of
   them and `Punycode.encode` takes one; an element that is not a
   one-character String raises `TypeError` from magnus's `char`
   conversion ("could not convert string to char, ..."), as Rust's type
   checker would refuse it. The labels and TLD `to_user_interface` and
   `process` pass their callback are Strings.
7. **`AsciiDenyList` is a value.** Its one field is private
   (`src/uts46.rs:272-274`), so Ruby cannot hold its bits; a Ruby
   `AsciiDenyList` holds a native one, frozen and shareable, made only by
   `new` and the three constants, never by Ruby's allocator. `==` is
   Rust's `PartialEq`, so `AsciiDenyList.new(false, "") ==
   AsciiDenyList::EMPTY`. Rust derives no `Hash`, so `eql?` and `hash`
   stay Ruby's identity. `new` asserts that the deny list holds no letter,
   digit, hyphen, dot, or non-ASCII byte (`:294-322`); the native layer
   checks each byte first, in the crate's order, and raises
   `ArgumentError` with the crate's assertion message, since idna has no
   error to refuse it with and the panic would otherwise end in
   `Errors` with a printed panic. A Rust test pins each message.
8. **The deprecated API.** `Config` and `Idna` are `#[deprecated]`, so
   `Ferro::Idna::Config` and `Ferro::Idna::Idna` are deprecated constants:
   naming one warns when `Warning[:deprecated]` is on, as plan 004 did for
   keyboard-types. `Idna#to_ascii(domain, out)` and `#to_unicode(domain,
   out)` append to `out`, a String, as Rust's `&mut String` does, and
   raise `Errors` (or return `nil`). `out` frozen raises `FrozenError`.
   `use_idna_2008_rules(true)` panics in idna (`src/deprecated.rs:204-214`);
   the native layer refuses it first with `ArgumentError` and the crate's
   assertion message, "IDNA 2008 rules are no longer supported".
9. **`Config` is a value too.** Its fields are private and its setters
   take `self` by value and return it (`src/deprecated.rs:155-214`); since
   `Config` is `Copy`, the receiver a Rust caller holds is unchanged. Ruby
   matches that: each setter returns a new frozen `Config`, and the
   receiver stays as it was. A Config crosses to Rust as its four flags.
10. **Enums.** As plans 002 to 004: unit variants are frozen instances
    whose `inspect` is the constant, with `==` by identity, since each
    enum derives `PartialEq`. None derives `Ord` or `Hash`, so none is
    Comparable. `Hyphens`, `DnsLength`, and `ErrorPolicy` are
    `#[non_exhaustive]`; Ruby has nothing to translate that to beyond the
    RDoc saying more variants may come.
11. **`ProcessingError` raises.** `process` returns
    `Result<ProcessingSuccess, ProcessingError>`, and ADR 001 has a
    `Result` raise. `ProcessingError` is not a Rust `Error` and has no
    `Display`, so Ruby's `Uts46::ProcessingError < StandardError` has a
    subclass per variant whose message is the variant's `Debug` text,
    `ValidityError` or `SinkError`. With `ErrorPolicy::MarkErrors`, the
    output idna wrote before the error stays in the caller's sink, which
    is the caller's String, so raising loses nothing. `SinkError` cannot
    happen: a String sink never fails (decision 14).
12. **`verify_dns_length`'s debug assertion.** It "Panics in debug mode if
    the argument isn't ASCII" (`src/uts46.rs:456-463`). The gem builds in
    release mode, where `debug_assert!` compiles to nothing, so a
    non-ASCII argument gets idna's length verdict; the RDoc says so. A
    debug build would raise `Errors` (`idna panicked: ...`), not end the
    process.
13. **The `output_as_unicode` callback.** idna calls an `FnMut(&[char],
    &[char], bool) -> bool` for each label that needs a decision.
    `to_user_interface` takes it as a block or as any object that
    responds to `call`, not both; `process` takes it as a positional
    argument, since its two sinks follow it. Each call gets the label and
    the TLD as Strings and the bidi flag, and its result is truthy or
    not. idna calls it with the GVL held, so Ruby code runs inside the
    crate's processing. An exception the callback raises stops further
    calls (each later call answers `false`, Punycode) and is raised again
    when idna returns, so the result idna computed is dropped. ToASCII is
    the callback `->(*) { false }` and ToUnicode `->(*) { true }`, as
    idna's docs say (`src/uts46.rs:716-720`).
14. **Sinks are Strings.** `process` writes to a `W: Write`, and the
    caller reads what it wrote. Ruby's `sink` and `ascii_sink` are
    Strings, which idna's output is appended to after it returns,
    whether it succeeded or raised `ValidityError`; `ascii_sink` may be
    `nil`, Rust's `None`. A Rust `String` is the sink inside, so idna's
    `SinkError` never arises. Taking any object with `<<` was rejected:
    idna writes piece by piece, so a Ruby sink would run Ruby code for
    every piece and turn a Ruby exception into a `SinkError` that loses
    it. A frozen sink raises `FrozenError` before idna runs.
15. **No panic reaches Ruby.** Every idna call runs under `catch_unwind`
    (decision 3). The panics reachable from Ruby are refused first
    (decisions 7 and 8). The `unreachable!` arms on `SinkError`
    (`src/uts46.rs:583-584`, `:688-689`) cannot run with a String sink,
    and `From<PunycodeEncodeError>` (`:441-447`) cannot, since idna caps
    the input it encodes (`PUNYCODE_ENCODE_MAX_INPUT_LENGTH`, `:44`).
16. **GVL and Ractors.** Every call is short CPU work over in-memory
    tables, so every call keeps the GVL (plan 001, decision 14). idna's
    types are plain data, `Send` and `Sync`, and the extension keeps no
    Ruby value in a static, so it is marked Ractor-safe. Every Ruby value
    the gem makes is frozen and shareable: `AsciiDenyList`, `Config`,
    `Idna::Idna` (whose `to_ascii` takes `&mut self` but changes
    nothing, `src/deprecated.rs:76-129`), `Uts46::Uts46`, and every enum
    value. Windows runs the Ractor tests in a child process, for the Ruby
    4.0.9 barrier bug plan 001 found.
17. **Dependencies.** idna `=1.1.0` with its defaults; magnus `0.9.3` and
    rb-sys `0.9.130`. No other dependency.

## Tests

- Conformance (`test_uts46_conformance.rb`): idna's own
  `tests/uts46.rs`, ported: every line of `IdnaTestV2.txt`, read from the
  idna source Cargo unpacked to build the gem, through `Uts46#to_unicode`,
  `#to_ascii`, and `#process` with both sinks, with the same status rules
  and skips.
- Punycode (`test_punycode.rb`): `tests/punycode.rs` over
  `punycode_tests.json` and `bad_punycode_tests.json`, read the same way,
  through all four functions.
- The crate's unit tests (`tests/unit.rs`, `tests/unitbis.rs`): the
  examples, the Punycode prefix cases, emoji, bidi, and the deprecated
  `Config` paths (`tests/deprecated.rs`).
- Values and errors (`test_values.rb`): `AsciiDenyList` equality and every
  refused byte; `Config` immutability; enum instances; `Errors`'s message;
  `ProcessingError` classes; callbacks, their exceptions, and frozen
  sinks.
- Gem, Ractors (`test_gem.rb`, `test_ractor.rb`).
- Rust (`cargo test`): panic capture, the deny-list refusal messages
  against idna's real panics, and the `Debug` texts the Ruby side copies.

## Results

Every item above is bound. Nothing is deferred; the dropped rows (2, 25)
are Rust conversions with no Ruby meaning.

What the session found:

- idna 1.1.0's own conformance suite fails at this lockfile. idna ships
  `IdnaTestV2.txt` for Unicode 16.0.0 (its header says so), while the
  idna_adapter 1.2.2 Cargo locks reads ICU4X 2.4's newer Unicode data,
  which assigns code points those lines expect to be disallowed (`V7`).
  Run in a scratch copy of the crate against the same lockfile,
  `tests/uts46.rs` fails lines 3386, 4219, 4220, 4405, and 5858 to 5860,
  and `tests/deprecated.rs` those and 3384, 3385, 4401 to 4404, and 4408
  to 4411. The Ruby port asserts that exactly those lines fail and no
  others, so it agrees with Rust on all 6,000-odd lines, including the
  ones where the data moved on.
- magnus's `char` conversion already raises `TypeError` for a String that
  is not one character, so decision 6 uses it rather than a check of the
  gem's own.
- The native layer's class lookup first walked the path through
  `RModule`, which refuses a class, so a nested class such as
  `Uts46::ProcessingError::ValidityError` could not be raised from Rust;
  ferro-url's first nested `ParseError` found it. It now walks with
  `const_get` on any value.
- Two copies of the Unicode tables cost little: ferro-idna's whole
  extension is 0.77 MB on macOS, and ferro-url's, which carries the
  other copy, 1.0 MB.

ferro-idna holds no lock of its own, so the review's finding in ferro-url
(plan 005, Results), Ruby work while a native lock is held, has no
counterpart here. Its README now names the Unicode-3.0 license of the
ICU4X crates its build downloads.
