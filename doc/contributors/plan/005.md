# Plan 005: Bind url

Tauri reads every URL a plugin receives with the url crate, which follows
the WHATWG URL Standard, and an argument it cannot parse fails with url's
words: "relative URL without a base", "invalid port number". Ruby's `URI`
follows RFC 3986 instead and accepts and refuses different strings, so
Tokra's notification plugin hand-ported url 2.5.4's error paths
(`plugins/notification/lib/tokra/plugins/notification/url_check.rb`), with
a deviation for international domains that Ruby has no UTS 46 tables for
(Tokra's plan 024, decision 6). This plan adds `ferro-url` 0.1.0.pre.1,
which binds url 2.5.8, the latest release (crates.io, published
2026-01-05; the tag `v2.5.8` of https://github.com/servo/rust-url), so
Tokra can parse with the crate itself. [Plan 006](006.md) binds idna, which
url uses for hosts; [ADR 001](../adr/001.md) and plans [001](001.md) to
[004](004.md) hold the rules and lessons this plan follows.

ADR 001 skips crates that duplicate the standard library. url does not:
`URI` parses another grammar, has no WHATWG setters, no IDNA, no origin,
and no `application/x-www-form-urlencoded` serializer with url's
encodings. A Ruby program that must agree with a browser, or with Tauri,
needs the WHATWG parser.

## Naming

The gem is `ferro-url`, `require "ferro/url"`, module `Ferro::Url`,
extension `ferro_url`. The struct `url::Url` is `Ferro::Url::Url`, and the
crate's other root items sit beside it: `Ferro::Url::Host`, `Origin`,
`OpaqueOrigin`, `ParseError`, `SyntaxViolation`, `Position`,
`ParseOptions`, `PathSegmentsMut`, `UrlQuery`. The re-exported crate
`url::form_urlencoded` is `Ferro::Url::FormUrlencoded`, and the hidden
module `url::quirks` is `Ferro::Url::Quirks`.

## Design decisions

1. **One gem for url and its re-export.** url re-exports the whole
   form_urlencoded crate (`src/lib.rs:152`), and its own API returns
   form_urlencoded's types (`query_pairs`, `query_pairs_mut`), so
   `url::form_urlencoded` is part of url's public API and binds here as
   `Ferro::Url::FormUrlencoded`. url does not re-export idna or
   percent-encoding, so they get no API here; idna is ferro-idna's
   ([plan 006](006.md), which explains why two copies are harmless).
2. **Cargo features.** `std`, `serde`, and `expose_internals` are built.
   `serde` adds `Serialize` and `Deserialize` for `Url` (its string) and
   `Host`; Ruby has no serde, and the string serde writes is `Url#as_str`,
   which `Url.parse` reads, so it adds no Ruby API. `serialize_internal`
   and `deserialize_internal` exist only for a serde caller and are
   deferred with serde. `expose_internals` adds
   `quirks::InternalComponents` and `internal_components`, which are
   bound. `debugger_visualizer` cannot be built from the published crate:
   it embeds `../../debug_metadata/url.natvis` (`src/lib.rs:146-150`), a
   file in the repository (`debug_metadata/url.natvis` at `v2.5.8`) that
   the crates.io package leaves out, so rustc fails with "couldn't read
   ...url.natvis". It is off, the one exception to "every feature on",
   and it would add no Ruby API: it only tells a Windows debugger how to
   show a `Url`.
3. **`Url` is an entity.** Rust's setters change a `Url` in place, so the
   Ruby `Url` is a class whose object holds a native `Url` behind a
   `Mutex`, made only by native functions, never by Ruby's allocator.
   `dup` and `clone` copy it, as `Clone` does. A frozen `Url` refuses
   every setter with `FrozenError`, as a frozen Ruby object does, and
   `Ractor.make_shareable` freezes one and lets it cross Ractors, since
   `Url` is `Send` and `Sync`. Every mutation runs on the native value
   under `catch_unwind`; if url panics mid-change, the value is restored
   from a copy taken before, so the `Url` never holds broken offsets.
4. **Values.** As plans 002 to 004: `Host`'s and `Origin`'s variants are
   `Data` classes whose members take the names url binds them to
   (`Host::Domain(domain)`, `Host::Ipv4(address)`, `Host::Ipv6(address)`,
   `src/host.rs:66-75`; `Origin::Tuple(scheme, host, port)`,
   `src/origin.rs:81`; `Origin::Opaque(value)`, which url never names).
   `Host`'s derived `Ord` (`Domain` before `Ipv4` before `Ipv6`, then the
   value) is `<=>` with Comparable, computed by url. `OpaqueOrigin`'s one
   field is private (`src/origin.rs:113-115`), so the Ruby value holds the
   native one, made only by `Origin.new_opaque` and `Url#origin`; `==`,
   `eql?`, and `hash` are url's `Eq` and `Hash`. `SyntaxViolation` and
   `Position` are frozen instances; `SyntaxViolation#description` and
   `#to_s` are url's text.
5. **`ParseError`.** `ParseError < StandardError` has a subclass per
   variant, `EmptyHost` to `Overflow`, whose message is url's `Display`
   text (`src/parser.rs:88-99`), which a Rust test pins, typographic
   apostrophe in "doesn’t" included. A variant a later url adds raises
   the base class with url's text, since the enum is `#[non_exhaustive]`.
6. **`Result<_, ()>` raises `Ferro::Url::Error`.** Seven methods and four
   `quirks` setters return `Err(())`, an error with nothing in it. ADR
   001 has a `Result` raise, and Ruby needs a class to raise, so
   ferro-url adds `Ferro::Url::Error < StandardError`, as ferro-rfd added
   one for a crate with no error type (plan 002, decision 11). Its message
   names the method, `url::Url::set_port returned Err(())`, since `()`
   has no text. Returning `false` or `nil` was rejected: Rust marks these
   results `#[must_use]`, and a setter that fails silently in Ruby would
   be ignored where Rust's compiler warns. `Error` also carries the
   refusals in decisions 8 and 15 and a panic inside url
   (`url panicked: <message>`). It is not a `ParseError`, which stays
   url's own.
7. **`quirks` and `check_invariants` are bound though hidden.** Both are
   `pub` with `#[doc(hidden)]`: url's docs leave them out, but any Rust
   caller can use them, and url's own WPT tests run through `quirks`
   (`tests/wpt.rs`). `quirks` is the WHATWG URL API's getters and setters,
   which a Ruby program matching a browser needs. The RDoc says, as url's
   module doc does, that `Url`'s own methods are the usual choice.
   `check_invariants` returns `Result<(), String>`; `Ok` is `nil`, and
   the text of an `Err` raises `Error`.
8. **Borrowing builders hold their URL.** `query_pairs_mut` and
   `path_segments_mut` return values that borrow the `Url` mutably and
   restore its fragment or the rest of its serialization when dropped
   (`src/lib.rs:3211-3231`, `src/path_segments.rs:70-75`). Ruby has no
   borrow or scope-based drop, so the Ruby `PathSegmentsMut` and the
   `UrlQuery` a `Serializer` writes to hold the `Url`, and each method
   runs one whole cycle on it: `path_segments_mut()`, the operation, and
   the drop. That gives what one long-lived Rust value gives, because
   each operation edits only the path or the query and the drop restores
   the same suffix, and the `Url` is valid between calls, where Rust
   would not let you look at it. Making the Rust value is itself a
   change: url's `query_pairs_mut` adds the `?` of an empty query when
   the URL has none (`src/lib.rs:1701-1719`), so `http://a/b#f` becomes
   `http://a/b?#f` at once. Ruby's `query_pairs_mut` runs that empty
   cycle when it is called, as `path_segments_mut` runs its own to raise
   for a cannot-be-a-base URL. A `UrlQuery` keeps `finish`'s rule:
   after `finish`, which returns the `Url`, any call raises `Error` with
   form_urlencoded's panic text, `url::form_urlencoded::Serializer
   finished` (or `double finish` for a second `finish`), as Rust would
   panic. A String target is mutated in place, as `&mut String` is, and
   `Serializer.new` and `for_suffix` take one. `for_suffix` with a start
   past the end of the target panics in form_urlencoded
   (`fu:src/lib.rs:222-229`); the gem raises `ArgumentError` with its
   text instead. A start inside a character passes `for_suffix` but
   panics in `clear`, whose `String::truncate` needs a character
   boundary (`fu:src/lib.rs:241-244`), so the gem refuses it too, with
   `ArgumentError` and its own text, at `for_suffix` and before every
   operation, since the Ruby String may change between them. `Target` itself is not bound: Ruby code cannot
   implement a Rust trait, and String and `UrlQuery` are its impls.
9. **Iterators.** `path_segments`, `query_pairs`,
   `FormUrlencoded.parse`, and `FormUrlencoded.byte_serialize` return
   Enumerators. Each is computed from the crate's iterator when the
   method is called, so it does not change if the `Url` changes later,
   as the Rust borrow could not either. `Parse::into_owned` and
   `ParseIntoOwned` turn borrowed strings into owned ones and have no
   Ruby meaning (plan 001, decision 8). A pair is a two-element Array of
   UTF-8 Strings, decoded lossily as form_urlencoded does.
10. **`ParseOptions` and callbacks.** `ParseOptions` is `Copy` and each
    setter takes `self` by value (`src/lib.rs:252-316`), so the Ruby value
    is frozen and each setter returns a new one, leaving the receiver as
    it was. `base_url` takes a `Url` or `nil`, and `parse` copies the base
    before parsing, so a callback that changes the base cannot change the
    parse under way. `encoding_override` takes any callable from a String
    to a String whose bytes url uses, or `nil`; `syntax_violation_callback`
    takes a callable that receives each `SyntaxViolation`, or `nil`.
    url calls both inside the parse, with the GVL held. An exception from
    either stops further calls (the encoding falls back to UTF-8) and is
    raised once url returns. A `Serializer`'s `encoding_override` is the
    same callable; the gem calls it for every name and value before
    form_urlencoded runs, in the order form_urlencoded would, and hands
    form_urlencoded the results, so no Ruby code runs while the `Url` is
    locked (decision 20). `parse_with_params` and `extend_pairs` take any Enumerable of
    two-element pairs, a Hash included, as Rust takes any iterator of
    pairs.
11. **The GVL.** Every method is short CPU work and keeps the GVL (plan
    001, decision 14), except `socket_addrs`, which resolves a domain
    through the system's resolver (`(domain, port).to_socket_addrs()`,
    `src/lib.rs:1361-1365`) and can wait seconds. std cannot cancel a
    lookup, so the lookup runs on a thread of its own, and the Ruby
    thread waits on a channel with the GVL released and an unblocking
    function that sends the channel a message of its own (`gvl.rs`). An
    interrupt, Ctrl-C, `Thread#raise`, `Thread#kill`, or `Timeout`, ends
    the wait at once and runs; the lookup thread is abandoned to finish
    alone, as Ruby's own `Addrinfo.getaddrinfo` abandons its resolver
    thread (`ext/socket/raddrinfo.c:489-498`, `:554-618` at v4.0.9). An
    interrupt that raises nothing, a trap handler's, waits on. Unlike
    ferro-arboard's retry loop, which this replaced, the wait never falls
    back to running with the GVL held. url calls
    `default_port_number` only for a URL with a host and no port it knows
    (`:1356-1360`); the gem asks the same question first, calls the block
    with the GVL held when url would, and then runs url's `socket_addrs`
    with the answer, unlocked. The block is optional; without one it is
    `|| None`. An `io::Error` raises the `Errno` class of its OS code on
    Unix, and `IOError` with Rust's text otherwise, as ferro-rfd does
    (plan 002, decision 10); url's own "No host name in the URL" and "No
    port number in the URL" are `IOError`s.
12. **Network types.** Rust's `Ipv4Addr` and `Ipv6Addr` are Ruby's
    `IPAddr`, which Ruby code already uses for them; `set_ip_host` takes
    one, and anything else raises `TypeError`. A `SocketAddr` is an
    `Addrinfo` for the address and port; an IPv6 scope id becomes the
    address's `%` suffix, and the flow label, which `Addrinfo` cannot
    hold, is dropped.
13. **Paths.** `from_file_path` and `from_directory_path` take a String or
    an object with `to_path`, as Ruby's file methods do, but not through
    `File.path`, which refuses a NUL byte that a Rust path may hold and url
    percent-encodes (`tests/unit.rs`, `new_file_paths`); on Unix the bytes
    pass through, and on Windows a path is UTF-8. `to_file_path` returns a
    String in the file system's encoding. url's platform rules hold:
    Windows accepts a `file:` URL with a non-local host as a UNC path.
14. **Conversions.** `FromStr` and `TryFrom<&str>` are `Url.from_str` and
    `Url.try_from` (plan 004, decision 10). `Display` and
    `From<Url> for String` are `to_s`. `AsRef<str>` is `as_str`, not
    `to_str`: Ruby calls `to_str` implicitly wherever it wants a String,
    which would let a `Url` pass for one everywhere, a conversion Rust
    makes only on request. `Debug` is `inspect`, url's text
    (`Url { scheme: "https", ... }`), as ferro-rfd's dialogs show rfd's.
    `into_string` is deprecated in url, so it warns in Ruby's
    `:deprecated` category, naming `to_s` as Rust names `Into<String>`.
15. **Slicing.** `url[range]` takes a Range of `Position`s: endless
    (`Position::BeforePath..`), beginless (`...Position::AfterQuery`),
    bounded and exclusive (`Position::BeforeUsername...Position::AfterPort`),
    or `nil..nil` for the whole serialization, matching url's four `Index`
    impls. An inclusive bounded range raises `TypeError`, since url
    implements no `Index<RangeInclusive>`. Ruby builds a bounded Range
    only from values whose `<=>` answers, so `Position` has `<=>` in
    declaration order, which is also URL order; that `<=>` is Ruby's
    requirement, not url's, which derives no `Ord`. A range whose start
    falls after its end in the serialization would panic in Rust's string
    slicing; the gem raises `Error` instead.
16. **Text.** Every `&str` argument is a UTF-8 String (magnus converts, and
    raises `EncodingError` otherwise); the `&[u8]` arguments of
    `FormUrlencoded.parse` and `byte_serialize` take any String's bytes.
    Every result is UTF-8.
17. **No panic reaches Ruby.** Every url call runs under `catch_unwind`.
    The known panics reachable from Ruby are refused first
    (`for_suffix`, a finished `Serializer`, a backward slice). The rest
    need inputs over 4 GiB (`to_u32(...).unwrap()`, `src/parser.rs:1761-1768`)
    or broken internal offsets, which decision 3 rules out.
18. **Ractors (ADR 001, section 7).** url's types are `Send` and `Sync`,
    and the extension keeps no Ruby value in a static, so it is marked
    Ractor-safe. `Host`, `Origin`, `OpaqueOrigin`, `ParseOptions` without
    callbacks, `Position`, `SyntaxViolation`, and a frozen `Url` are
    shareable. Ractors sharing a `Url` contend for its lock, which is safe
    only because nothing of Ruby's happens under it (decision 20). Windows runs the Ractor tests in a child process, for the
    Ruby 4.0.9 barrier bug plan 001 found.
19. **Dependencies.** url `=2.5.8` with `serde` and `expose_internals`; form_urlencoded `=1.2.2`, url's own, named
    directly because the native layer writes to `Target`s; magnus `0.9.3`
    and rb-sys `0.9.130`. Ruby's `ipaddr` and `socket` (default gems) for
    decision 12. idna stays url's private dependency, and ferro-url's
    `test_gem.rb` fails if any package both lockfiles name, idna and the
    ICU4X crates and data under it, differs between them. Those ICU4X
    crates are Unicode-3.0; the source gem ships none of their code, so it
    carries no copy of that license, and a precompiled gem, which would,
    must ship `LICENSES/Unicode-3.0.txt`.
20. **Nothing of Ruby's under a `Url`'s lock.** A Ruby method call checks
    interrupts and can switch threads (`vm_eval.c:319` at v4.0.9), and an
    allocation can start a garbage collection that waits for every
    Ractor. If either happens while a thread holds a `Url`'s `Mutex`,
    another thread or Ractor blocked in that `Mutex` keeps the VM from
    ever giving the holder the GVL back or finishing the collection, and
    the process hangs past SIGTERM. So `NativeUrl::read` and `mutate`
    take closures that return Rust values and a Rust `Failure` (a
    `ParseError`, an `Err(())` by function name, a message, or a panic),
    and the lock is released before any Ruby value or exception, a class
    lookup included, is made. A host crosses as its owned `Host<String>`,
    copied under the lock and turned into Ruby values after. Callbacks
    run only on copies with no lock held (decision 10), and
    `socket_addrs` works on a copy too. `test_contention.rb` runs, in a
    child that is killed after 40 seconds, two threads raising and
    reading on one `Url` and four Ractors reading one shared `Url`; both
    hung with an exception built, or a host allocated, under the lock.

### Review

An independent review then found, and this session fixed:

- **Ruby work under a `Url`'s lock hung the VM.** Errors were built, a
  class looked up through `const_get`, inside `read` and `mutate`, and
  `host` made its Ruby Array there. A thread switch at the method call,
  or a garbage collection at the allocation, left another thread or
  Ractor blocked in the `Mutex` holding the VM, and the process hung past
  SIGTERM: thread A raising from `set_port` on `mailto:x@y` while thread
  B read it, and four Ractors reading one shared `Url`'s host. Work
  under the lock now returns Rust values and a `Failure` (decision 20).
  `test_contention.rb` hung (killed after 40 s) with either pattern put
  back and passes now.
- **`query_pairs_mut` did not add url's `?`** (decision 8), now tested.
- **`socket_addrs` could not be interrupted** and, after three skipped
  tries, resolved with the GVL held. It now runs on its own thread and
  waits interruptibly (decision 11); Rust tests drive the wait with a slow
  fake lookup, and `test_gvl.rb` ends a wait with `Timeout` and
  `Thread#raise` through `Native.gvl_sleep`. With the unblocking function
  a no-op, the `Timeout` test fails.
- **`for_suffix` inside a character panicked in `clear`**, now refused
  (decision 8), with a Rust test that shows form_urlencoded's panic.
- `Encodings::finish`'s never-encoded branch had no test; it has one.
- Steep's targets now come from `FERRO_GEMS`, with each gem's
  `rbs_libraries`, and a tooling test checks the arguments
  `rbs:validate` builds.
- `test_gem.rb` compares every package both gems' lockfiles name.
- Both READMEs name ICU4X's Unicode-3.0 license (decision 19).

The same audit of the other gems, for any Ruby call or allocation while a
native lock is held:

- **ferro-notify-rust had the bug.** `Notification`'s field readers made
  Ruby Strings and Arrays under the notification's `Mutex`, which
  `frozen_shareable` lets Ractors share; four Ractors reading one shared
  notification hung, reproduced by putting an allocation back under the
  lock. The readers now copy the field out and build Ruby values after,
  `with` and `with_ref` build their error after the lock is released, as
  does the Linux handle's `shared`, and `test_ractor.rb` gains the
  contention test. Its CHANGELOG records the fix.
- **ferro-arboard** built its result under the lock on its fast path.
  Every other caller there takes the lock with `try_lock` or waits for it
  with the GVL released, so nothing could hang, but the result is now
  built after the lock is released all the same.
- **ferro-rfd**'s future builds a refusal while its slot is locked, but
  every caller takes that lock with `try_lock` and refuses when it is
  busy, so no thread ever waits on it; left as is.
- **ferro-global-hotkey** locks only its graveyard `Vec`, with no Ruby
  work under it; nothing to change. ferro-idna has no lock.

Unverified here: Windows, which never ran. ferro-url's Windows-only code

`io_errno`'s `None`; its Windows tests (`new_path_windows_fun`,
`test_windows_unc_path`, the Windows branches of the file-path tests) are
url's own, ported, and run first in CI. A DNS failure there is an
`io::Error` with a Winsock code, which the gem raises as `IOError`.
