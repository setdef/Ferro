# Plan 005: Bind url

Tauri reads every URL a plugin receives with the url crate, which follows
the WHATWG URL Standard, and an argument it cannot parse fails with url's
words: "relative URL without a base", "invalid port number". Ruby's `URI`
follows RFC 3986 instead and accepts and refuses different strings, so
Tokra's notification plugin hand-ported url 2.5.4's error paths
(`plugins/notification/lib/tokra/plugins/notification/url_check.rb`), with
a deviation for international domains that Ruby has no UTS 46 tables for
(Tokra's plan 024, decision 6). This plan adds `ferro-url` 0.1.0.pre.1,
which binds url 2.5.8, the latest release (crates.io, published
2026-01-05; the tag `v2.5.8` of https://github.com/servo/rust-url), so
Tokra can parse with the crate itself. [Plan 006](006.md) binds idna, which
url uses for hosts; [ADR 001](../adr/001.md) and plans [001](001.md) to
[004](004.md) hold the rules and lessons this plan follows.

ADR 001 skips crates that duplicate the standard library. url does not:
`URI` parses another grammar, has no WHATWG setters, no IDNA, no origin,
and no `application/x-www-form-urlencoded` serializer with url's
encodings. A Ruby program that must agree with a browser, or with Tauri,
needs the WHATWG parser.

## Naming

The gem is `ferro-url`, `require "ferro/url"`, module `Ferro::Url`,
extension `ferro_url`. The struct `url::Url` is `Ferro::Url::Url`, and the
crate's other root items sit beside it: `Ferro::Url::Host`, `Origin`,
`OpaqueOrigin`, `ParseError`, `SyntaxViolation`, `Position`,
`ParseOptions`, `PathSegmentsMut`, `UrlQuery`. The re-exported crate
`url::form_urlencoded` is `Ferro::Url::FormUrlencoded`. The hidden module
`url::quirks` is not bound (decision 7).

## Design decisions

1. **One gem for url and its re-export.** url re-exports the whole
   form_urlencoded crate (`src/lib.rs:152`), and its own API returns
   form_urlencoded's types (`query_pairs`, `query_pairs_mut`), so
   `url::form_urlencoded` is part of url's public API and binds here as
   `Ferro::Url::FormUrlencoded`. url does not re-export idna or
   percent-encoding, so they get no API here; idna is ferro-idna's
   ([plan 006](006.md), which explains why two copies are harmless).
2. **Cargo features.** `std`, `serde`, and `expose_internals` are built.
   `serde` adds `Serialize` and `Deserialize` for `Url` (its string) and
   `Host`; Ruby has no serde, and the string serde writes is `Url#as_str`,
   which `Url.parse` reads, so it adds no Ruby API. `serialize_internal`
   and `deserialize_internal` exist only for a serde caller and are
   deferred with serde. `expose_internals` adds only
   `quirks::InternalComponents` and `internal_components`, inside the
   hidden `quirks` module the gem does not bind (decision 7), so it is
   off (ADR 002: it reaches only Rust). `debugger_visualizer` cannot be built from the published crate:
   it embeds `../../debug_metadata/url.natvis` (`src/lib.rs:146-150`), a
   file in the repository (`debug_metadata/url.natvis` at `v2.5.8`) that
   the crates.io package leaves out, so rustc fails with "couldn't read
   ...url.natvis". It is off too, and it would add no Ruby API: it only tells a Windows debugger how to
   show a `Url`.
3. **`Url` is an entity.** Rust's setters change a `Url` in place, so the
   Ruby `Url` is a class whose object holds a native `Url` behind a
   `Mutex`, made only by native functions, never by Ruby's allocator.
   `dup` and `clone` copy it, as `Clone` does. A frozen `Url` refuses
   every setter with `FrozenError`, as a frozen Ruby object does, and
   `Ractor.make_shareable` freezes one and lets it cross Ractors, since
   `Url` is `Send` and `Sync`. Freezing a `Url` (or cloning a frozen one)
   freezes its native value too, and every native setter refuses a frozen
   native value through magnus's `check_frozen`, which works like Ruby's
   `rb_check_frozen` but sets no `FrozenError#receiver`, so not even
   private methods reach a frozen `Url` through another wrapper. Every
   mutation runs on the native value under `catch_unwind`; if url panics
   mid-change, the value is restored from a copy taken before, so the
   `Url` never holds broken offsets.
4. **Values.** As plans 002 to 004: `Host`'s and `Origin`'s variants are
   `Data` classes whose members take the names url binds them to
   (`Host::Domain(domain)`, `Host::Ipv4(address)`, `Host::Ipv6(address)`,
   `src/host.rs:66-75`; `Origin::Tuple(scheme, host, port)`,
   `src/origin.rs:81`; `Origin::Opaque(value)`, which url never names).
   `Host`'s derived `Ord` (`Domain` before `Ipv4` before `Ipv6`, then the
   value) is `<=>` with Comparable, computed by url. `OpaqueOrigin`'s one
   field is private (`src/origin.rs:113-115`), so the Ruby value holds the
   native one, made only by `Origin.new_opaque` and `Url#origin`; `==`,
   `eql?`, and `hash` are url's `Eq` and `Hash`. `SyntaxViolation` and
   `Position` are frozen instances; `SyntaxViolation#description` and
   `#to_s` are url's text.
5. **`ParseError`.** `ParseError < StandardError` has a subclass per
   variant, `EmptyHost` to `Overflow`, whose message is url's `Display`
   text (`src/parser.rs:88-99`), which a Rust test pins, typographic
   apostrophe in "doesn’t" included. A variant a later url adds raises
   the base class with url's text, since the enum is `#[non_exhaustive]`.
6. **`Result<_, ()>` raises `Ferro::Url::Error`.** Nine functions on `Url`
   and six `quirks` setters return `Err(())`, an error with nothing in it. ADR
   001 has a `Result` raise, and Ruby needs a class to raise, so
   ferro-url adds `Ferro::Url::Error < StandardError`, as ferro-rfd added
   one for a crate with no error type (plan 002, decision 11). Its message
   names the method, `url::Url::set_port returned Err(())`, since `()`
   has no text. Returning `false` or `nil` was rejected: Rust marks these
   results `#[must_use]`, and a setter that fails silently in Ruby would
   be ignored where Rust's compiler warns. `Error` also carries a panic
   inside url that the gem does not refuse first (`url panicked:
   <message>`). It is not a `ParseError`, which stays url's own. The
   panics the gem does refuse first raise Ruby's own classes with Rust's
   message (ADR 001, 2026-11-05, the error rule): `RangeError` for a
   backward slice (decision 15), `ArgumentError` for a `Serializer`
   start position form_urlencoded cannot use, and `IOError` for a
   finished or dropped `Serializer` or a dropped `PathSegmentsMut`
   (decision 8).
7. **Hidden and deprecated items are not bound.** ADR 001's amendment of
   2026-11-05 leaves an item marked `#[doc(hidden)]` or `#[deprecated]`
   unbound unless Tauri needs it. url 2.5.8 has three: the `quirks` module
   (`src/lib.rs:223-224`), `check_invariants` (`:686`), and `into_string`
   (`:676`, deprecated since 2.3.0 for `Into<String>`, which is `to_s`).
   Tauri calls none of them (no `url::quirks`, `check_invariants`, or
   url `into_string` in `vendor/tauri`; its `into_string` calls are
   serialize_to_javascript's), and Tokra calls none, so round one's
   bindings of all three are gone, with `Quirks::InternalComponents` and
   the `expose_internals` feature that exists for it (decision 2).
   form_urlencoded 1.2.2 has no hidden or deprecated item. url's own
   tests reach `quirks` and `check_invariants`, so their ports changed:
   `test_wpt.rb` runs `urltestdata.json` through `ParseOptions` and
   reads the URL Standard's getters as `quirks.rs` computes them from
   `Url`'s public API (`src/quirks.rs:82-336`), but no longer runs
   `setters_tests.json`, whose setters drive url's private parser; and the
   unit-test ports drop their `check_invariants` assertions and the six
   tests that call `quirks` (`test_set_empty_hostname`, `test_set_href`,
   `test_domain_encoding_quirks`, `test_expose_internals`, `no_panic`, and
   `issue_974`).
8. **Borrowing builders hold their URL.** `query_pairs_mut` and
   `path_segments_mut` return values that borrow the `Url` mutably and
   restore its fragment or the rest of its serialization when dropped
   (`src/lib.rs:3211-3231`, `src/path_segments.rs:70-75`). Ruby has no
   borrow or scope-based drop, so the Ruby `PathSegmentsMut` and the
   `UrlQuery` a `Serializer` writes to hold the `Url`, and each method
   runs one whole cycle on it: `path_segments_mut()`, the operation, and
   the drop. That gives what one long-lived Rust value gives, because
   each operation edits only the path or the query and the drop restores
   the same suffix, and the `Url` is valid between calls, where Rust
   would not let you look at it. Making the Rust value is itself a
   change: url's `query_pairs_mut` adds the `?` of an empty query when
   the URL has none (`src/lib.rs:1701-1719`), so `http://a/b#f` becomes
   `http://a/b?#f` at once. Ruby's `query_pairs_mut` runs that empty
   cycle when it is called, as `path_segments_mut` runs its own to raise
   for a cannot-be-a-base URL.

   ADR 001's amendment of 2026-11-05 gives a block form wherever Rust
   ties something to the end of a scope, so both methods take one: the
   block is the Rust value's scope, gets the value, and returns its
   value, as `File.open`'s does, and when it ends, however it ends, the
   value is dropped, and any later call on it raises `IOError`, as a
   closed IO does. Without a block both still return the value, which is
   Rust's own common shape, a temporary dropped at the end of its
   statement (`url.path_segments_mut().map_err(..)?.pop().push("img")`,
   url's doc example, `src/path_segments.rs:21-40`); the per-call cycle
   keeps that shape working with the same serialization, so it stays. The
   block form does not hold the change back until the block ends: that
   would mean holding url's value, and the `Url`'s lock, across Ruby code
   (decision 20), and the cycle already gives what one long-lived value
   gives.

   A `Serializer` keeps `finish`'s rule: `finish` takes the target out
   (`fu:src/lib.rs:344-349`), so the serializer is spent, and any later
   call raises `IOError`, as a consumed value does under ADR 001's error
   rule, with form_urlencoded's panic text,
   `url::form_urlencoded::Serializer finished` (or `double finish` for a
   second `finish`), where Rust would panic. `encoding_override` does not
   touch the target, so it works after `finish`, as in Rust. A String
   target is mutated in place, as `&mut String` is, and `Serializer.new`
   and `for_suffix` take one. `for_suffix` with a start past the end of
   the target panics in form_urlencoded (`fu:src/lib.rs:222-229`); the gem
   raises `ArgumentError` with its text instead, at `for_suffix` and
   before every operation, which runs `for_suffix` again on a String that
   may have changed. A start inside a character passes `for_suffix` and
   the appends but panics in `clear`, whose `String::truncate` asserts a
   character boundary (`fu:src/lib.rs:241-244`), so the gem refuses `clear`
   alone, with `ArgumentError` and std's text, `assertion failed:
   self.is_char_boundary(new_len)`, which a Rust test drives. Round one
   refused such a start everywhere, with text of its own, which refused
   calls form_urlencoded accepts. `Target` itself is not bound: Ruby code
   cannot implement a Rust trait, and String and `UrlQuery` are its impls.
9. **Iterators.** ADR 001's amendment of 2026-11-05 makes a method that
   returns `impl Iterator` an Enumerator, and an iterator type a class
   with Rust's `next` (`nil` at the end), `each`, and `Enumerable`, never
   an Array. form_urlencoded's `Parse` and `ByteSerialize` are iterator
   types, so `FormUrlencoded::Parse` and `FormUrlencoded::ByteSerialize`
   bind them: `FormUrlencoded.parse` and `Url#query_pairs` (which url
   types as `Parse`, `src/lib.rs:1509`) return the first, and
   `FormUrlencoded.byte_serialize` the second. Each holds form_urlencoded's
   own iterator, made by the crate's own function (`Url::query_pairs` on
   a copy of the `Url` taken under its lock), and calls its `next` once
   per Ruby `next`, so nothing is decoded or encoded before it is asked
   for. A Ruby object outlives the call that made it, and Rust's iterator
   borrows its input, so the native layer keeps the iterator with an
   `Arc` of what it borrows (`iter.rs`, `Owned`), which takes the one
   `unsafe` lifetime extension that pairing needs, justified in its
   `SAFETY` comment. `Owned::new` is an `unsafe fn`, since its soundness
   rests on the closure that builds the iterator not letting the borrow
   escape; its `# Safety` section states that, and each caller's `SAFETY`
   comment says why the iterator it builds keeps the borrow to itself. `each` yields what remains and leaves the iterator
   at the end, as Rust's `for` over `iter.by_ref()` does, so `Enumerable`
   reads from where the iterator stands. `Parse` is `Copy`, so `dup`
   copies it where it stands; `ByteSerialize` is neither `Copy` nor
   `Clone`, so `dup` raises `TypeError`, Ruby's class for an object it
   cannot copy; and `ByteSerialize#size_hint` is its own
   (`fu:src/lib.rs:165-171`). `path_segments` returns std's `Split`, not
   a crate type, so it is an Enumerator, computed when the method is
   called, so it does not change if the `Url` changes later, as the Rust
   borrow could not either. `Parse::into_owned` and `ParseIntoOwned`
   turn borrowed strings into owned ones and have no Ruby meaning (plan
   001, decision 8). A pair is a two-element Array of UTF-8 Strings,
   decoded lossily as form_urlencoded does. Round one returned an
   Enumerator over a collected Array from all four; `path_segments` still
   does. Neither url nor form_urlencoded has a `Duration` anywhere in its
   public API, so the amendment's `Duration` row changes nothing here.
10. **`ParseOptions` and callbacks.** `ParseOptions` is `Copy` and each
    setter takes `self` by value (`src/lib.rs:252-316`), so the Ruby value
    is frozen and each setter returns a new one, leaving the receiver as
    it was. `base_url` takes a `Url` or `nil`, and `parse` copies the base
    before parsing, so a callback that changes the base cannot change the
    parse under way. `encoding_override` takes any callable from a String
    to a String whose bytes url uses, or `nil`; `syntax_violation_callback`
    takes a callable that receives each `SyntaxViolation`, or `nil`.
    url calls both inside the parse, with the GVL held. An exception from
    either stops further calls (the encoding falls back to UTF-8) and is
    raised once url returns. A `Serializer`'s `encoding_override` is the
    same callable; the gem calls it for every name and value before
    form_urlencoded runs, in the order form_urlencoded would, and hands
    form_urlencoded the results, so no Ruby code runs while the `Url` is
    locked (decision 20). `parse_with_params` and `extend_pairs` take any Enumerable of
    two-element pairs, a Hash included, as Rust takes any iterator of
    pairs.
11. **The GVL.** Every method is short CPU work and keeps the GVL (plan
    001, decision 14), except `socket_addrs`, which resolves a domain
    through the system's resolver (`(domain, port).to_socket_addrs()`,
    `src/lib.rs:1361-1365`) and can wait seconds. std cannot cancel a
    lookup, so the lookup runs on a thread of its own, and the Ruby
    thread waits on a channel with the GVL released and an unblocking
    function that sends the channel a message of its own (`gvl.rs`). An
    interrupt, Ctrl-C, `Thread#raise`, `Thread#kill`, or `Timeout`, ends
    the wait at once and runs; the lookup thread is abandoned to finish
    alone, as Ruby's own `Addrinfo.getaddrinfo` abandons its resolver
    thread (`ext/socket/raddrinfo.c:489-498`, `:554-618` at v4.0.9). An
    interrupt that raises nothing, a trap handler's, waits on. Unlike
    ferro-arboard's retry loop, which this replaced, the wait never falls
    back to running with the GVL held. url calls
    `default_port_number` only for a URL with a host and no port it knows
    (`:1356-1360`); the gem asks the same question first, calls the block
    with the GVL held when url would, and then runs url's `socket_addrs`
    with the answer, unlocked. The block is optional; without one it is
    `|| None`. If the operating system will not start the lookup thread,
    the lookup runs on the calling thread instead, with the GVL still
    released but with no way to interrupt it, which is url's own behavior;
    round one raised `Error` with text of its own there, and ADR 001's
    error rule makes the gem's machinery fall back rather than refuse. An `io::Error` raises the `Errno` class of its OS code on
    Unix, and `IOError` with Rust's text otherwise, as ferro-rfd does
    (plan 002, decision 10); url's own "No host name in the URL" and "No
    port number in the URL" are `IOError`s.
12. **Network types.** Rust's `Ipv4Addr` and `Ipv6Addr` are Ruby's
    `IPAddr`, which Ruby code already uses for them; `set_ip_host` takes
    one, and anything else raises `TypeError`. A `SocketAddr` is an
    `Addrinfo` for the address and port; an IPv6 scope id becomes the
    address's `%` suffix, and the flow label, which `Addrinfo` cannot
    hold, is dropped.
13. **Paths.** `from_file_path` and `from_directory_path` take a String or
    an object with `to_path`, as Ruby's file methods do, but not through
    `File.path`, which refuses a NUL byte that a Rust path may hold and url
    percent-encodes (`tests/unit.rs`, `new_file_paths`); on Unix the bytes
    pass through, and on Windows a path is UTF-8. `to_file_path` returns a
    String in the file system's encoding. url's platform rules hold:
    Windows accepts a `file:` URL with a non-local host as a UNC path.
14. **Conversions.** `FromStr` and `TryFrom<&str>` are `Url.from_str` and
    `Url.try_from` (plan 004, decision 10). `Display` and
    `From<Url> for String` are `to_s`. `AsRef<str>` is `as_str`, not
    `to_str`: Ruby calls `to_str` implicitly wherever it wants a String,
    which would let a `Url` pass for one everywhere, a conversion Rust
    makes only on request. `Debug` is `debug` (decision 21).
    `into_string` is deprecated in url and unbound (decision 7).
15. **Slicing.** `url[range]` takes a Range of `Position`s: endless
    (`Position::BeforePath..`), beginless (`...Position::AfterQuery`),
    bounded and exclusive (`Position::BeforeUsername...Position::AfterPort`),
    or `nil..nil` for the whole serialization, matching url's four `Index`
    impls. An inclusive range, bounded or beginless
    (`..Position::AfterQuery`), raises `TypeError`, since url implements
    no `Index<RangeInclusive>` or `Index<RangeToInclusive>`. Ruby builds a
    bounded Range only from values whose `<=>` answers, so `Position` has
    `<=>` in declaration order, which is also URL order; that `<=>` is
    Ruby's requirement, not url's, which derives no `Ord`, so `Position`
    has nothing more (no `Comparable`). A range whose start
    falls after its end in the serialization would panic in Rust's string
    slicing; the gem refuses it first with `RangeError`, Ruby's class for a
    range it cannot use, and std's panic text, `byte range starts at 21
    but ends at 19`, which a Rust test drives through url's own `Index`.
    Round one raised `Error` with text of its own.
16. **Text.** Every `&str` argument is a UTF-8 String (magnus converts, and
    raises `EncodingError` otherwise); the `&[u8]` arguments of
    `FormUrlencoded.parse` and `byte_serialize` take any String's bytes.
    Every result is UTF-8.
17. **No panic reaches Ruby.** Every url call runs under `catch_unwind`.
    The known panics reachable from Ruby are refused first
    (`for_suffix`, `clear` from inside a character, a finished
    `Serializer`, a backward slice, url's `Debug` for a `PathSegmentsMut`
    over a URL with a query or a fragment), with Ruby's classes and Rust's
    text (decision 6). The last needs offsets url keeps private, which the
    native layer reads from the URL the guard was made on (decision 21),
    so no panic reaches Rust's panic hook, which would print it. The rest
    need inputs over 4 GiB (`to_u32(...).unwrap()`, `src/parser.rs:1761-1768`)
    or broken internal offsets, which decision 3 rules out.
18. **Ractors (ADR 001, section 7).** url's types are `Send` and `Sync`,
    and the extension keeps no Ruby value in a static, so it is marked
    Ractor-safe. `Host`, `Origin`, `OpaqueOrigin`, `ParseOptions` without
    callbacks, `Position`, `SyntaxViolation`, and a frozen `Url` are
    shareable. Ractors sharing a `Url` contend for its lock, which is safe
    only because nothing of Ruby's happens under it (decision 20). Windows runs the Ractor tests in a child process, for the
    Ruby 4.0.9 barrier bug plan 001 found.
19. **Dependencies.** url `=2.5.8` with `serde` and `expose_internals`; form_urlencoded `=1.2.2`, url's own, named
    directly because the native layer writes to `Target`s; magnus `0.9.3`
    and rb-sys `0.9.130`. Ruby's `ipaddr` and `socket` (default gems) for
    decision 12. idna stays url's private dependency, and ferro-url's
    `test_gem.rb` fails if any package both lockfiles name, idna and the
    ICU4X crates and data under it, differs between them. Those ICU4X
    crates are Unicode-3.0; the source gem ships none of their code, so it
    carries no copy of that license, and a precompiled gem, which would,
    must ship `LICENSES/Unicode-3.0.txt`.
20. **Nothing of Ruby's under a `Url`'s lock.** A Ruby method call checks
    interrupts and can switch threads (`vm_eval.c:319` at v4.0.9), and an
    allocation can start a garbage collection that waits for every
    Ractor. If either happens while a thread holds a `Url`'s `Mutex`,
    another thread or Ractor blocked in that `Mutex` keeps the VM from
    ever giving the holder the GVL back or finishing the collection, and
    the process hangs past SIGTERM. So `NativeUrl::read` and `mutate`
    take closures that return Rust values and a Rust `Failure` (a
    `ParseError`, an `Err(())` by function name, a message, or a panic),
    and the lock is released before any Ruby value or exception, a class
    lookup included, is made. A host crosses as its owned `Host<String>`,
    copied under the lock and turned into Ruby values after. Callbacks
    run only on copies with no lock held (decision 10), and
    `socket_addrs` works on a copy too. `test_contention.rb` runs, in a
    child that is killed after 40 seconds, two threads raising and
    reading on one `Url` and four Ractors reading one shared `Url`; both
    hung with an exception built, or a host allocated, under the lock.

21. **`Debug`.** ADR 001's amendment of 2026-11-05 gives a type that
    implements `Debug` a `debug` method answering the crate's text, which
    Rust formats (`format!("{:?}", value)` in the native layer on a real
    value, so the text cannot drift), and leaves `inspect` as Ruby's;
    round one's `inspect`s that imitated `Debug` (`Url`, `OpaqueOrigin`)
    or printed the constant path (`Position`, `SyntaxViolation`) are gone,
    and `Data`'s own `inspect` stays. Every public type, and whether it
    implements `Debug`:

    A Ruby `PathSegmentsMut` stands for one long-lived Rust value, but
    makes a fresh one for each call (decision 8), and the fields a
    long-lived one keeps differ: `old_after_path_position` stays where it
    was when the value was made. So the Ruby value keeps a copy of the URL
    as it was when made and the calls made on it, and `debug` makes a real
    `PathSegmentsMut` on that copy, runs the same calls, and formats it.
    url's own `Debug` for a value over a URL with a query or a fragment is
    broken: `take_after_path` cuts the query and fragment from the
    serialization but keeps their offsets (`src/lib.rs:1721-1730`), and
    `Url`'s `Debug` then reads them, so it panics (`start byte index 22 is
    out of bounds for string of length 21` in a release build, a
    `debug_assert` before that in a debug one) or, after a call that
    lengthens the path, shows bytes from the wrong place. The gem formats
    what url formats, and refuses first where url would panic (decision
    17): `guard_debug_panic` takes the query and fragment offsets from
    the URL the guard was made on, through `Position`, and the guard's
    shorter serialization from a copy of that URL with `set_query(None)`
    and `set_fragment(None)` and the same calls run on it; then, in
    `Debug`'s field order (`path`, `query`, `fragment`), it finds the first
    slice std would refuse, and `debug` raises `ArgumentError` with std's
    text for it (`slice_panic`, std's `slice_error_fail_rt` in
    `library/core/src/str/mod.rs`). Where every slice falls inside, `debug`
    answers url's text, wrong bytes and all. The serialization is ASCII,
    so only the out-of-bounds texts arise, but `slice_panic` words every
    case std does. One Rust test drives `slice_panic` against std's own
    panic, ASCII and not; another drives the prediction against url's real
    `Debug` for eight guards. `cargo test` builds in the dev profile, where
    url's `debug_assert!(self.byte_at(..) == ..)` in `query` and `fragment`
    (`src/lib.rs:1475-1479`, `:1547`) panics before their slice with other
    text, while `path` has none; the gem is built in release. So the test
    compares the real panic wherever a debug build reaches the slice
    (`path`'s, and the cases that do not panic in release), checks only
    that a debug build panics otherwise, and under `cargo test --release`
    compares every case. The prediction's texts are also written into the
    test, so the dev profile pins them too. A Ruby `PathSegmentsMut`
    records each call with frozen copies of its segments, so a caller who
    changes a String or Array after passing it cannot change `debug`.
    The pure-Ruby mirrors (the enums, the error classes) send the
    variant's name to a native function that builds the Rust value and
    formats it, as ferro-idna does (plan 006, decision 18).

### Review

An independent review then found, and this session fixed:

- **Ruby work under a `Url`'s lock hung the VM.** Errors were built, a
  class looked up through `const_get`, inside `read` and `mutate`, and
  `host` made its Ruby Array there. A thread switch at the method call,
  or a garbage collection at the allocation, left another thread or
  Ractor blocked in the `Mutex` holding the VM, and the process hung past
  SIGTERM: thread A raising from `set_port` on `mailto:x@y` while thread
  B read it, and four Ractors reading one shared `Url`'s host. Work
  under the lock now returns Rust values and a `Failure` (decision 20).
  `test_contention.rb` hung (killed after 40 s) with either pattern put
  back and passes now.
- **`query_pairs_mut` did not add url's `?`** (decision 8), now tested.
- **`socket_addrs` could not be interrupted** and, after three skipped
  tries, resolved with the GVL held. It now runs on its own thread and
  waits interruptibly (decision 11); Rust tests drive the wait with a slow
  fake lookup, and `test_gvl.rb` ends a wait with `Timeout` and
  `Thread#raise` through `Native.gvl_sleep`. With the unblocking function
  a no-op, the `Timeout` test fails.
- **`for_suffix` inside a character panicked in `clear`**, now refused
  (decision 8), with a Rust test that shows form_urlencoded's panic.
- `Encodings::finish`'s never-encoded branch had no test; it has one.
- Steep's targets now come from `FERRO_GEMS`, with each gem's
  `rbs_libraries`, and a tooling test checks the arguments
  `rbs:validate` builds.
- `test_gem.rb` compares every package both gems' lockfiles name.
- Both READMEs name ICU4X's Unicode-3.0 license (decision 19).

The same audit of the other gems, for any Ruby call or allocation while a
native lock is held:

- **ferro-notify-rust had the bug.** `Notification`'s field readers made
  Ruby Strings and Arrays under the notification's `Mutex`, which
  `frozen_shareable` lets Ractors share; four Ractors reading one shared
  notification hung, reproduced by putting an allocation back under the
  lock. The readers now copy the field out and build Ruby values after,
  `with` and `with_ref` build their error after the lock is released, as
  does the Linux handle's `shared`, and `test_ractor.rb` gains the
  contention test. Its CHANGELOG records the fix.
- **ferro-arboard** built its result under the lock on its fast path.
  Every other caller there takes the lock with `try_lock` or waits for it
  with the GVL released, so nothing could hang, but the result is now
  built after the lock is released all the same.
- **ferro-rfd**'s future builds a refusal while its slot is locked, but
  every caller takes that lock with `try_lock` and refuses when it is
  busy, so no thread ever waits on it; left as is.
- **ferro-global-hotkey** locks only its graveyard `Vec`, with no Ruby
  work under it; nothing to change. ferro-idna has no lock.

## Follow-up: the GVL is never held

An audit of errors the gems make themselves found the defect plan 001's
follow-up fixed in ferro-arboard here too, in a different shape. `gvl.rs`
released the GVL with `rb_thread_call_without_gvl2`, which skips the work
whenever any interrupt is pending (`thread.c:320-327` at Ruby v4.0.9),
and its loop answered a skipped wait by running the interrupts and trying
again, without bound. An interrupt Ruby holds back stays pending, which is
certain inside a user-defined `Exception#backtrace`: Ruby calls it with
the thread marked as raising (`eval.c:542-543`, `error.c:1929`), and a
thread so marked runs no interrupts (`thread.c:2625`). There
`socket_addrs` spun forever with the GVL held, and every Ruby thread
stopped with it. The fallback that runs the lookup on the calling thread
when no thread starts (decision 11) looped the same way. The released
0.1.0.pre.1 has the defect, so the CHANGELOG records the fix.

`gvl.rs` now takes ferro-arboard's design (plan 001, Follow-up: the GVL
is never held). It calls the plain `rb_thread_call_without_gvl`, which
always runs its function, inside magnus's public `protect` (magnus
`src/rb_sys.rs:186-191`, `src/error.rs:449-510`, behind its `rb-sys`
feature, which adds no crate). Ruby runs pending interrupts before
releasing the GVL, proceeding even when the thread is marked as raising
(`thread.c:319-343`), and again after taking it back (`:1636-1638`); an
interrupt that raises jumps out with `longjmp`, which `protect` turns into
an `Err` that magnus raises once the method's Rust values are dropped. The
jump skips only the closure `protect` runs, which holds raw pointers, as
magnus's own `thread_check_ints` does (`src/thread.rs:404-410`). The
lookup thread and the channel-based unblocking function stay: an
interrupt that raises ends the wait and abandons the lookup, and one that
raises nothing (`Thread#wakeup`, a trap that returns) lets `drive` wait
again, with no `thread_check_ints` of its own, since Ruby has already run
it. The fallback makes the same call with no unblocking function, so an
interrupt takes effect once the lookup returns (`thread.c:1676-1679`).

An interrupt that arrives after the lookup answered but before the GVL is
back raises then, and the addresses are dropped. Ruby's own IO does the
same: `rb_thread_io_blocking_call` checks interrupts after a read or write
returns (`thread.c:1986-1999`), and one that raises there discards what it
read. The passage on `rb_thread_call_without_gvl` calls that check harmful
for work that has finished and recommends `rb_thread_call_without_gvl2`
for such work (`thread.c:1685-1699`); this follow-up rejects that function
on purpose, because it skips the work while any interrupt is pending, and
the interrupt Ruby holds back stays pending, which is what made the loop
spin. A lookup has no side effect to lose, and without the release the
interrupt would fire as the method returned all the same. The RDoc of
`socket_addrs` says so.

The tests no longer read a clock. The private `Native.gvl_sleep`, whose
tests counted a spinning thread's progress and timed an interrupt, is
gone. In its place `Native.gvl_hold_lookups` holds every lookup that
starts, on the lookup's own thread, until a test lets it go, and
`Native.gvl_refuse_threads` makes `start` fail as an operating system out
of threads would, so the fallback, which no test reached before, runs, and
the private `Native.gvl_fallbacks` counts each lookup it runs on the
calling thread, so both fallback tests assert that it ran, and a normal
lookup test that it did not.
The lookups resolve `localhost`, which the system answers without the
network. Each test that sets a switch runs in a child Ruby, which a
deadlock cannot outlive. A thread waiting on a held lookup sleeps, so the
tests wait for that status: the main thread letting the lookup go shows
other threads run during the wait; `Thread#raise`, `Thread#kill`, and
`Timeout` end a wait whose lookup is still held; `Thread#wakeup` grows
the release count and leaves the thread waiting for the addresses. Two
tests call `socket_addrs` from inside an `Exception#backtrace` with
`Thread#wakeup` pending, once with a lookup thread and once with the
fallback, and a releaser thread lets the lookup go only once the caller
sleeps in the released call, so the addresses prove the other thread ran.
The Rust tests drive the wait with a lookup gated on a channel rather than
a sleep.
