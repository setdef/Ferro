# Plan 009: time's deferred groups

[Plan 007](007.md) bound time 0.3.55 as ferro-time 0.1.0.pre.1 and
deferred, each whole, seven groups: `Timestamp`; `Parsed` with every
`parse_with_defaults`; the `iter` module with `iter_from` and `iter_to`;
version 1 and 2 and `strftime` format descriptions with the format-item
tree they return; the `unit` module; std's unsigned `Duration` and the
operations that take it; and `SignedDuration`'s precision `Display`. This
plan binds as many as fit in coherent, fully tested batches, in the order
users meet them, and defers the rest whole, with a reason. It binds two:
the format-item tree with versions 1 and 2 and `strftime`, and `Parsed`
with every `parse_with_defaults` but `Timestamp`'s.

The order follows use. A Rubyist who reads time's book writes
`[year]-[month]-[day]` and wants the items back, or ports a Rust program
that builds `Component::Day(modifier::Day::default())`; that comes first.
`Parsed` and `parse_with_defaults` build on the items (`parse_item` takes
one), so they come second. `Timestamp`, std's `Duration`, `unit`, `iter`,
and the precision `Display` stand alone and follow.

The crate, its version, its license, and the Rust-to-Ruby rules are plan
007's; this plan cites only what it adds. Citations are `file:line` in
time 0.3.55's `src/` unless they name another crate.

## Design decisions

1. **Scope.** Batches 1 and 2 are one feature from a user's side: the
   items a description parses into, and the parser state those items
   fill. Each later row is a group of its own, bound whole or deferred
   whole, so no type is half-bound.
2. **Modifier enums.** As plan 007, decision 4: frozen instances whose
   `inspect` is the constant, equal by identity, with a private index the
   native layer reads. time's three current enums derive `Default` as a
   public trait, so each has `.default`; the deprecated six implement
   `Default` too, through the same macro (`modifier.rs:56-222`), so they
   have it as well. `Padding::None` is a constant named `None`, which
   Ruby allows and which is time's variant name.
3. **Modifiers are `Data` classes whose `new` is private.** Every modifier
   is a `Copy` struct with derived `PartialEq`, a value object, so each is
   a frozen `Data` class and equality, `hash`, and `eql?` are `Data`'s,
   which compare what Rust's derives compare. time makes none of them
   constructible outside the crate: those with public fields are
   `#[non_exhaustive]`, and the rest keep their fields `pub(crate)`. A
   Rust caller builds one from `default()` (or `Ignore::count`, since
   `Ignore` has no default, `modifier.rs:1030-1037`) and the `with_*`
   builders, so in Ruby `new` is private and `.default`, `Ignore.count`,
   and `#with_*` (which return a new value through `Data#with`) are the
   way in. A field time keeps `pub(crate)` has a private reader, so
   `respond_to?(:case_sensitive)` answers as Rust's visibility does;
   `Data#to_h` and pattern matching still see it, as time's own `Debug`
   prints it. Each builder checks its argument's type, as Rust's type
   checker would: a Padding where time takes a `Padding`, `true` or
   `false` for a `bool`, an Integer from 1 to 65,535 for `NonZero<u16>`,
   raising `TypeError` or `RangeError` in Ruby's words otherwise.
4. **Enums with data are modules of `Data` classes.** As ferro-url's
   `Host` (plan 005): `Component`, `BorrowedFormatItem`, and
   `OwnedFormatItem` are modules, and each variant is a `Data` class that
   includes its module, so `is_a?(Component)` answers for every variant.
   A tuple variant's one field takes the name time's own code gives it
   when it matches the variant: `modifier` for a component (time's
   `Component::Day(modifier)`, `component.rs:126-170`), and `literal`,
   `component`, `compound`, `item`, and `items` for the items (their
   `Debug`, `borrowed_format_item.rs:44-57`). Every variant's `new` is
   public, as Rust's are, and checks its field's type. A `Compound` or
   `First` holds a frozen Array and a literal a frozen String, so every
   item is deeply frozen and shareable, as a Rust value no method
   changes.
5. **Borrowed and owned items.** Lifetimes have no Ruby meaning, so the
   two enums differ in Ruby only by class: a borrowed item holds Ruby
   values as an owned one does. They stay apart because time keeps them
   apart: their names, their conversions, and `PartialEq`, which never
   compares one with the other. Both cross into Rust as an
   `OwnedFormatItem`, through time's own `From<&BorrowedFormatItem>`
   (`owned_format_item.rs:85-107`), as plan 007 already owned a borrowed
   version 3 description. time formats the two through separate code
   (`formatting/formattable.rs:540-664`: a borrowed component through
   `Component::format_into`, an owned one through the version 3 path), so
   a Rust test formats every component variant, with every modifier
   setting and every deprecated variant, through both and asserts the
   same bytes and errors on all six value types. Parsing shares one path
   (`parsing/parsed.rs:53-127`).
6. **Deprecations.** time deprecates the old components, their modifiers
   and enums, both `Literal` variants, `FormatItem`, and `parse`. Ruby's
   counterpart of `#[deprecated]` on a type or variant is
   `Module#deprecate_constant`: Ruby warns, in the `:deprecated` category,
   where code names one, as rustc warns where Rust code names one. The
   deprecated `parse` warns as `Util.days_in_year_month` does. The gem's
   own code reaches the deprecated classes through private constants
   kept before the deprecation, so it never warns on a user's behalf.
7. **Debug.** `inspect` is time's `Debug`, as plan 007's decision 12 has
   it: the native layer builds the Rust value and formats it.
   `Day { padding: Zero }`, `Day(Day { padding: Zero })`, and for items
   time's own hand-written `Debug`, which writes a literal bare and a
   compound as a list: `[Day(Day { padding: Zero }), -]`. `to_s` stays
   `Data`'s, since time implements no `Display` for any of them.
8. **Conversions.** As plan 007, decision 5: `From` is `.from`, `TryFrom`
   is `.try_from`. `BorrowedFormatItem.from` takes a component or an
   Array of borrowed items; `OwnedFormatItem.from` takes a component, a
   borrowed item, or an Array of borrowed or of owned items (an empty
   Array is an empty compound either way), and refuses anything else
   with `TypeError`. `Component.try_from(item)` raises
   `Error::DifferentVariant`, the first thing in the gem that raises it.
   Rust's `TryFrom<Item>` for a slice or `Vec` converts into Ruby's Array,
   which a library must not reopen; `Compound#compound` reads the same
   items. `PartialEq<Component>` holds both ways (`Component#==` and the
   `Component` items' `==` answer each other), and a `Compound` is `==`
   to an Array of the same items. The reverse, `array == compound`, would
   need `Array#==` to change, or a `to_ary` that makes every compound
   splat; both are dropped. `eql?` and `hash` stay strict, as Rust's
   `Eq` is per type.
9. **Versions 1 and 2, and `strftime`.** `parse_borrowed(1 or 2, s)` and
   `parse_strftime_borrowed(s)` return an Array of BorrowedFormatItem, as
   Rust returns a `Vec`; the Array is the caller's and not frozen, as a
   `Vec` is the caller's to change. `parse_owned(1 or 2, s)` and
   `parse_strftime_owned(s)` return one OwnedFormatItem, a `Compound`.
   The version check is plan 007's: anything but 1, 2, or 3 raises
   `TypeError` with time's assertion.
10. **Items as descriptions.** `format`, `format_into`, and `parse` take a
    BorrowedFormatItem, an OwnedFormatItem, or an Array of either (Rust's
    slices), and refuse a mixed Array with `TypeError`, as Rust has no
    slice of both. The Ruby side encodes the tree into nested Arrays of
    Integers, Strings, and booleans the native layer rebuilds, field for
    field, through time's public `default` and `with_*`; the reverse,
    for the parsers' output, reads `pub(crate)` fields by comparing the
    modifier with each `default().with_*` candidate, using only time's
    public API, and a Rust test round-trips every modifier setting. A
    tree nested deeper than 255 levels is refused with `ArgumentError` by
    `items.rs`'s `item_from`, which rebuilds the tree and counts its depth
    before anything is built past that depth or handed to time: time's own
    parser stops at that depth (a `u8` nesting count,
    `parse/lexer_ast.rs:330`, `:502-509`), while a deeper hand-built tree
    would run the native recursion, and time's, toward a stack overflow,
    which aborts the process rather than raising. Since `inspect` formats
    time's `Debug` through the same rebuild, `inspect` on such a tree
    raises the same `ArgumentError`.
11. **Concurrency.** Every value in batch 1 is frozen Ruby data and
    shareable; the native layer holds nothing between calls. Plan 005's
    decision 20 holds trivially.
12. **`Parsed` is a mutable class.** time's setters take `&mut self`, so
    a Ruby `Parsed` changes in place, as a Rust `let mut parsed` does. It
    is the gem's first mutable value: the native value sits behind a
    `Mutex`, held only to copy the `Copy` value out or back, while every
    crate call works on the copy, so neither Ruby nor time runs under the
    lock (plan 005, decision 20). Its class has an allocator, since `new`
    is time's `Parsed::new`, and `initialize_copy` copies the value, so
    `dup` and `clone` are Rust's `Clone`; like Ruby's own, it refuses to
    overwrite a frozen `Parsed`. A frozen `Parsed` raises Ruby's
    own `FrozenError` from every method that would change it, in Ruby
    and again in each native setter and `parse_*`, as the iterators'
    natives check (plan 010), and the
    class is not frozen-shareable, so a `Parsed` never crosses Ractors.
    time derives no `PartialEq`, so `==` is identity.
13. **Setters and builders.** A setter returns `Option<()>`: `true` when
    time took the value, `nil` when it refused, as plan 007's decision 13
    translated `refresh_tz`, since `nil` alone could not tell the two
    apart. A builder returns a new `Parsed` or `nil`. Months and weekdays
    cross as the gem's constants; a `NonZero` argument of zero raises
    `RangeError` in magnus's words for an Integer out of a Rust type's
    range, as `Modifier::Ignore.count` does.
14. **Hidden, deprecated accessors.** `offset_minute`, `offset_second`,
    and their `set_` and `with_` forms (`#[doc(hidden)]`, deprecated since
    0.3.8, `parsing/parsed.rs:770-797`, `:891-928`, `:1092-1124`) are
    dropped, as plan 007 dropped `time_fn`; the `_signed` forms replace
    them.
15. **Bytes in, bytes out.** `parse_item`, `parse_items`,
    `parse_component`, `Parsed.parse_literal`, and `parse_with_defaults`
    take `&[u8]` in Rust, so they read a Ruby String's bytes whatever its
    encoding, and the `parse_*` methods return the rest of the input as a
    binary String, as Rust returns the rest of its slice. `parse_item`
    takes one item and `parse_items` an Array, as Rust's take one item and
    a slice. `parse_with_defaults` copies its defaults, as Rust takes
    `Parsed` by value.
16. **Errors alone.** `Parsed`'s methods fail with time's
    `ParseFromDescription`, and `TryFrom<Parsed>` with `TryFromParsed`,
    outside a `Parse`, so they raise the top-level
    `Error::ParseFromDescription` and `Error::TryFromParsed` variants,
    which plan 007 defined and nothing raised until now; `parse` and
    `parse_with_defaults` still raise the variants nested under
    `Error::Parse`.
17. **Formatting a literal that is not UTF-8.** time's `format` passes its
    output through `String::from_utf8_lossy` when a description may write
    bytes that are not UTF-8 (`formatting/formattable.rs:291-313`), which
    the deprecated `Literal` items can. Plan 007's `format` refused
    invalid UTF-8 as a panic, which no version 3 or well-known description
    could reach; it now replaces the bytes as time does. `format_into`
    still appends the raw bytes, as Rust's writer gets them.
18. **What waits.** Each remaining group is a batch of its own, and none
    is half-bound. `Timestamp` is a seventh instant type with about eighty
    items, interop with three types and `SystemTime`, and a 983-line test
    file; its `parse_with_defaults` and `TryFrom<Parsed>` wait with it.
    std's `Duration` needs an unsigned value type Ruby lacks and some
    forty operations across every type. `unit` is const-generic (a `u128`
    `N` on every unit) and picks a Rust numeric type per conversion,
    neither of which Ruby has; the `SignedDuration` constants already give
    the same numbers. `iter` needs a Ruby design for Rust's double-ended,
    exact-size iterators. The precision `Display` is a Rust formatter
    option, which Ruby's `to_s` cannot take without an invented argument.
    Plan 011's fixes later bound it anyway, as `SignedDuration#to_s(precision)`,
    with the precision alone and no width or fill.
19. **`UtcDateTime` past the range, a fix to 0.1.0.pre.1.** time's
    `TryFrom<Parsed>` for `UtcDateTime` builds the local date-time and
    calls the panicking `to_utc` (`parsing/parsed.rs:1336-1341`), and every
    `UtcDateTime.parse`, released in 0.1.0.pre.1, goes through it, so
    `9999-12-31 23:00 -05` raised "time panicked" with Rust's panic on
    standard error, against plan 007's decision 7. `try_from`, `parse`,
    and `parse_with_defaults` now first take the same input, or the same
    `Parsed`, through `OffsetDateTime`'s conversion, which runs time's
    `UtcDateTime` steps one for one (unix timestamp, leap-second stand-in,
    date, time, offset) but keeps the offset, and refuse with
    `RangeError` and `to_utc`'s message, "local datetime out of valid
    range", when `checked_to_utc` has no answer. A missing offset hour
    means UTC, which cannot leave the range. One case escapes the public
    API: a leap second (second 60, which only the well-known formats
    allow) whose instant is not a month's last, where `OffsetDateTime`
    refuses before it builds the instant and time's `Time` will not
    convert the parsed hour and minute. There the gem runs time's own
    conversion with the panic caught quietly, by a hook installed at load
    that stays silent only while that call runs on this thread and prints
    every other panic as before (each extension links its own std, so the
    hook governs this gem only), and turns `to_utc`'s panic into the same
    refusal. Rust tests compare the refusal with time's real panic at
    both ends; a fuzz of 600,000 `try_from`, `parse` (version 3, RFC 3339,
    ISO 8601), and `parse_with_defaults` calls near both ends of the range,
    with random offsets, leap seconds, and unix timestamps, found no panic
    and nothing on standard error.

### Decisions

20. **One class, `UtcDateTime`'s pattern.** `Timestamp` is a seventh
    wrapped value (`NTimestamp`), frozen as it is made, shareable, with
    the shared `eq`, `hash`, `cmp`, `display`, and `debug` natives and the
    private `new` of every value class. Its readers answer one number or
    one tuple through two natives, as `datetime.rs`'s do; it has no
    `truncate_to_*` and no `unix_timestamp` (its `as_*` methods are the
    names time gives them), so it has its own module, `timestamp.rs`,
    rather than another run of that file's macro.
21. **The fraction of a negative instant.** A `Timestamp` is whole
    seconds and a forward nanosecond count, so half a second before the
    epoch is seconds -1 and 500,000,000 ns, and `timestamp!(-1.5)` is -2
    and 500,000,000. `replace_millisecond`, `replace_microsecond`, and
    `replace_nanosecond` (`:1220-1296`) special-case an instant before
    the epoch whose fraction is not zero: they replace the fraction as its
    decimal text writes it, so replacing the fraction of `-1.5` with
    400 ms gives `-1.4`, where `UtcDateTime`'s clock nanosecond gives
    `-1.6`, and replacing it with 0 gives `-1`. A whole negative second
    has no special case: `new(-1, 0).replace_millisecond(400)` is `-0.6`,
    as a clock gives. The gem keeps time's behavior; the RDoc of the three
    methods and the README say so, and the ported `replace_*` tests pin it.
22. **Panics refused, each with time's message.** Every conversion that
    ends in an `expect` is checked first, and `Result::expect` words its
    panic with the error's `Debug`, which the gem copies:
    - `+` and `-` with a `SignedDuration` call `checked_add` and
      `checked_sub` and refuse with "resulting value is out of range"
      (`:1458-1462`, `:1507-1511`).
    - `to_offset` calls `checked_to_offset` and refuses with "local
      datetime out of valid range" (`:302-310`).
    - `From<OffsetDateTime>` panics when the offset puts the instant past
      the range (`interop/offsetdatetime_timestamp.rs:63-78`); the gem
      asks `Timestamp::from_seconds` first and refuses with time's text
      and the error's `Debug`, "local datetime out of valid range for
      `Timestamp`: ComponentRange { name: \"seconds\", is_conditional:
      false }".
    - `From<SystemTime>` panics when the instant is past the range
      (`interop/systemdatetime_timestamp.rs:67-86`); the gem refuses with
      "SystemTime value is out of valid range: ComponentRange {...}". Its
      step back of one second for a negative fraction overflows `i64` only
      at the span `i64::MIN`, where Rust panics in a debug build and wraps
      into the same failure in a release build; the gem names that
      failure in both. `Timestamp.now` takes the same conversion.
    - `Timestamp - SystemTime` subtracts or adds a std `Duration` from the
      span since the epoch (`:8-20`), which panics inside `SignedDuration`
      for a `::Time` far from the epoch: "overflow converting
      `std::time::Duration` to `time::SignedDuration`: ConversionRange",
      "overflow when subtracting durations", or "overflow when adding
      durations". The gem runs the same two steps with the checked
      operations first (`duration::sub`, `duration::add`).
    - `From<Timestamp> for SystemTime` adds the span to the epoch
      (`:93-100`), which std refuses where `SystemTime` is narrower
      (Windows, before 1601). The gem reuses `system_after_epoch`, the
      check `OffsetDateTime`'s conversion already makes, now shared.
      Windows counts a `SystemTime` in 100 ns from 1601, so a `::Time`
      keeps whole 100 ns intervals there, as plan 007, decision 10 says,
      and the Windows-only test is read, not run, here.
    Rust tests compare each refusal with time's real panic over 4,000
    seeded inputs near both ends of the range; `test_timestamp.rb` pins
    the Ruby side; a fuzz over `new`, the conversions, arithmetic,
    `to_offset`, `parse` (RFC 3339 and ISO 8601, leap seconds included),
    `parse_with_defaults`, and `try_from` found no panic (Results).
23. **`TryFrom<Parsed>` and parsing.** With a Unix timestamp in the
    `Parsed`, time returns `from_nanoseconds`; without one it takes the
    `UtcDateTime` conversion and answers its instant, or
    `InsufficientInformation` for any failure of it (`parsing/parsed.rs:1395-1410`).
    That swallowing is time's: `Timestamp.parse("2016-12-30T23:59:60Z",
    Rfc3339)` raises `InsufficientInformation` where `UtcDateTime` raises
    `ComponentRange` for the same leap second. The `UtcDateTime` step is
    the panicking `to_utc` of decision 19, so `Timestamp`'s `try_from`,
    `parse`, and `parse_with_defaults` take decision 19's refusal
    unchanged (`utc_refusing`, now generic over the type it converts to).
    A `Parsed` cannot hold a Unix timestamp past `Timestamp`'s range, so
    the `from_nanoseconds` failure in the fast path has no input.
24. **Formatting.** A `Timestamp` supplies a date, a clock time, an
    offset of UTC, and a Unix timestamp
    (`formatting/component_provider.rs:453-560`), so it formats with every
    description exactly as `UtcDateTime` does, RFC 2822 and RFC 3339
    included; a test compares the two over four instants and eight
    descriptions, including `format_into`'s count.
25. **`Display` and `Debug`.** Both write the seconds, then the fraction
    without trailing zeros (`:1380-1448`): `1234567890.123`, `-0.5`. A
    negative instant writes its magnitude, so `-1 s + 400 ms` is `-0.6`.
    Rust's width and fill (`f.pad`) are formatter machinery with no
    `to_s` counterpart (plan 007, decision 12).
26. **std's `Duration` stays deferred** (decision 18): T19 binds nothing,
    and `Timestamp` has no public `checked_add_std`, so no method is
    half-bound.
27. **A garbage-collection crash found by the fuzz.** An error's
    arguments (a `ComponentRange`'s name) were held in a `Vec<Value>` on
    Rust's heap while `Class#new` allocated the exception, so Ruby's
    collector, which scans the stack and not the heap, could free the name
    string before `initialize` read it: a segmentation fault at
    `error.rb:108` after enough raised errors, in 0.1.0.pre.2. The
    arguments now sit in a three-slot array on the machine stack, which
    Ruby scans conservatively (magnus 0.9.3 `src/into_value.rs:154-158`);
    no error takes more than three, and an assertion keeps a fourth from
    slipping in. Registering them with `BoxValue` was tried and refused:
    it edits a VM-wide list without a lock on Ruby 4.0.9 (`gc.c:3444-3488`)
    and crashed eight parallel Ractors raising errors. `GC.stress` makes
    the old crash certain in a child Ruby
    (`test_an_error_keeps_its_arguments_through_a_collection`), and
    `test_many_ractors_raise_errors_at_once` makes the `BoxValue` crash
    certain.
    ferro-notify-rust had the same bug and is fixed in its own change.
