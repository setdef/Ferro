# Plan 001: Bootstrap Ferro and Bind arboard

Ferro exists because of Tokra's ADR 011: crate bindings leave Tokra's
plugins and become gems of their own, each answering to one crate. This
plan builds the repository and its pilot gem, `ferro-arboard`, which binds
arboard 3.7.0, the latest release. [ADR 001](../adr/001.md) restates the
decisions this plan carries out.

### Design decisions

1. **The public API is Ruby; the native layer is one private method per
   terminal operation.** Rust defines `Clipboard` (a magnus-wrapped
   `Mutex<arboard::Clipboard>`), `Clipboard.new`, and private methods such
   as `native_get_text(selection)` and `native_set_text(text, options)`.
   `Get`, `Set`, and `Clear` are Ruby objects that hold their clipboard and
   the settings their extension methods chose, and their terminal methods
   call the native method with those settings. This gives every public
   method real RDoc, RBS that Steep checks against code, and a native layer
   small enough to audit line by line. The alternative, native builder
   objects holding a reference to the clipboard, keeps more Rust and leaves
   RDoc nothing to read.
2. **Builders mutate and return themselves.** Rust's extension methods
   consume `self` and return `Self` (`src/platform/linux/mod.rs:383-408`).
   Ruby has no moves, so `set.wait` records the setting and returns the same
   `Set`, and a terminal method may run more than once. arboard builds its
   platform `Get`, `Set`, or `Clear` at the terminal call instead of at
   `clipboard.get`, which changes nothing observable except on Windows,
   where opening the clipboard (`src/platform/windows.rs:581`, `:665`, `:888`)
   moves from builder creation to the terminal call. `Get.new`, `Set.new`,
   and `Clear.new` are private, as arboard's fields are `pub(crate)`.
3. **Errors.** `Error < StandardError` with one subclass per variant. Rust
   raises each with `to_string()` of the crate's error, so the crate's
   `Display` is the message; each class also defaults to that text when you
   raise it yourself. `Unknown` takes the description and builds the message
   in the crate's format (`src/common.rs:62`). `Error` is `#[non_exhaustive]`
   (`src/common.rs:19`): a variant a future arboard adds raises the base
   `Error` with its `Display` text until Ferro adds a class for it.
4. **Images arboard would panic on raise `ConversionFailure` before they
   reach arboard.** A width or height of zero, or a byte count other than
   `width * height * 4`, is refused on every platform. arboard 3.7.0 would
   panic on a wrong byte count on Linux and Windows, where the image
   crate's PNG encoder asserts the length (`image-0.25.10
   src/codecs/png.rs:740-746`, reached from
   `src/platform/linux/mod.rs:38-46` and `src/platform/windows.rs:132-144`),
   and on macOS it unwraps `CGDataProviderCreateWithData`
   (`src/platform/osx.rs:58-69`). Refusing every such shape on every
   platform keeps one answer: macOS would otherwise accept an oversized
   buffer silently. Tokra's plan 016, item 6 found this panic in 3.6.1
   (https://git.sr.ht/~kerrick/tokra/tree/trunk/item/doc/contributors/plan/016.md).
   The check, `is_drawable_rgba`, and its Rust tests come from Tokra's
   clipboard binding; their author, the copyright holder of both projects,
   relicensed them from AGPL-3.0-or-later to MIT OR Apache-2.0 for Ferro.
5. **No panic reaches Ruby as `fatal`.** magnus turns a panic in a bound
   method into Ruby's `fatal`, which `rescue` cannot catch
   (`magnus-0.9.3 src/error.rs:292-296`, `src/method.rs:340-345`). Every call
   into arboard runs under `std::panic::catch_unwind` inside the clipboard's
   lock, so the lock is never poisoned, and a panic raises the base
   `Ferro::Arboard::Error` with the message `arboard panicked: <message>`.
   It is not a crate variant because arboard never returned it. A lock
   poisoned anyway is recovered (`PoisonError::into_inner`), since arboard's
   clipboard holds no invariant a panic could break.
6. **`wait_until` takes a monotonic deadline.** Rust's `Instant` is a point
   on the monotonic clock. Ruby's equivalent is
   `Process.clock_gettime(Process::CLOCK_MONOTONIC)`, a Float, so
   `wait_until(deadline)` takes one. At the terminal call Ruby passes the
   seconds remaining, and Rust adds them to `Instant::now()`. A deadline in
   the past waits for nothing, as an `Instant` in the past does. A NaN or
   infinite deadline raises `RangeError` with Rust's own wording, since
   Rust code could not build such an `Instant` without panicking.
7. **`LinuxClipboardKind` is a class with three frozen instances** named for
   the variants, so `LinuxClipboardKind::Primary` reads as it does in Rust.
   A `selection` that is not one of them raises `TypeError`, as Rust's type
   checker would refuse it. The instances answer only `inspect`; the
   builders read the variant name privately, since arboard's enum has no
   method to convert it.
8. **Ownership helpers are dropped.** `ImageData::into_owned_bytes` and
   `to_owned_img` turn borrowed bytes into owned ones (`src/common.rs:133-150`).
   Ruby has no borrowed bytes, so `image.bytes` and the image itself already
   are what they return. ADR 001's table drops lifetime machinery.
9. **`Debug` maps to Ruby's own `inspect`.** Exceptions already inspect as
   class and message, which carries what arboard's `Debug` carries (variant
   name and `Display` text).
10. **Paths.** `Set#file_list` takes Strings or objects with `to_path`
    (`File.path` converts them, as Ruby's own file methods do). On Unix
    the bytes pass through unchanged; on Windows a path must be UTF-8.
    `Get#file_list` returns Strings.
11. **Text must be UTF-8.** arboard takes `str`; magnus converts a Ruby
    String to UTF-8 and raises `EncodingError` when it cannot.
12. **Clipboard lifetime.** arboard asks that every clipboard be dropped
    before the program exits (`src/lib.rs:38-43`). Ruby frees each wrapped
    object at a normal exit (`gc.c:338-350` at v4.0.1, which calls the free
    function of every typed data object), so the clipboard drops then, or
    when the garbage collector frees it. `exit!` and a crash skip it.
13. **Ractors (ADR 001, section 7).** arboard's `Clipboard` is `Send` and
    `Sync` (`src/lib.rs:510-516` asserts it; `src/platform/osx.rs:105-106`),
    and the wrapper adds a `Mutex`, so the class is `frozen_shareable`:
    `Ractor.make_shareable(clipboard)` works. The extension is marked
    Ractor-safe with `rb_ext_ractor_safe(true)` in `Init_`, which magnus
    does not wrap; its `SAFETY` comment walks Ruby's checklist
    (`doc/extension.rdoc:2207-2286` at v4.0.1). A non-main Ractor can open
    a clipboard or use a shared one; without the call it would raise
    `Ractor::UnsafeError` (`test_ractor.rb`).
14. **The GVL is released around the calls that can block** (`src/gvl.rs`):
    on Linux, every read, which polls the owning program for up to four
    seconds (arboard `src/platform/linux/x11.rs:101`, `:371-378`; Wayland
    reads a pipe the owner writes), and every write with `wait`,
    `wait_until`, or `wait_once` (`x11.rs:281-296`, `wayland.rs:63-68`).
    Every other call keeps the GVL. Releasing it for every call was tried
    first, and a reviewer measured about 330 ms per `get_text` with three
    busy threads: retaking the GVL waits out a time slice per competing
    thread, which Ruby warns about for short calls (`thread.c:1721-1723` at
    v4.0.1). macOS reads have no wait of their own (`osx.rs:135-153`,
    `:224-249`), and Windows' open retries last at most about 25 ms
    (`windows.rs:533-560`).

    magnus does not wrap `rb_thread_call_without_gvl`, so rb-sys's binding
    is called directly, with the `2` variant: the plain one checks
    interrupts after reacquiring the lock and can raise from there, a
    `longjmp` across Rust frames (`thread.c:1636-1638`). Arguments become
    Rust values before the lock is released and results become Ruby values
    after; the work catches its own panics. The clipboard's `Mutex` is taken
    without the GVL on that path. A short call takes it with `try_lock`
    while holding the GVL, and if another thread holds it (through a long
    wait, say) waits for it with the GVL released instead, so it never
    stalls the VM. There is no unblocking function, because arboard cannot
    cancel a call in progress: Ctrl-C and `Thread#kill` take effect when the
    call returns, and process exit waits for it (`thread.c:484-493`). When
    an interrupt is pending, Ruby skips the work; the interrupt runs through
    magnus's protected `thread_check_ints` and the work is tried again.
    After three skips, which needs an interrupt being raised already
    (`thread.c:2625`) or a new one each try, the work runs with the GVL
    held, and there a busy lock reports `ClipboardOccupied` rather than
    waiting. Dropping a clipboard on X11 can block up to 100 ms plus a
    thread join during a GC sweep, with the GVL held (`x11.rs:790`,
    `:1105-1135`). `drive`, the retry loop, takes Ruby's two calls as
    arguments so Rust tests cover each path; `test_gvl.rb` checks that
    Linux reads let a spinning thread run and that short reads elsewhere do
    not; `test_linux.rb` ports arboard's `wait` test with a Ruby thread as
    the replacer.
15. **Dependencies.** arboard `3.7.0` with `image-data` and
    `wayland-data-control`, magnus `0.9.3` with `bytes` (its safe way to copy
    a String's bytes, which Tokra also enables), and rb-sys `0.9.130`. Tokra
    pins magnus to git revision `2370a352` because no released 0.9 existed
    then; 0.9.3 contains that revision plus 53 later commits, among them the
    Ruby 4.1 typed-data fix, and a registry release installs without git.
    The manifest pins arboard with `=3.7.0`, since the Ruby API mirrors
    exactly that release; moving to another is a deliberate change, not a
    `cargo update`.
16. **An `Option` parameter stays a parameter.** `set_html` takes
    `alt_text: Option<T>` (`src/lib.rs:110-116`), so Ruby's `set_html` takes
    two arguments and you pass `nil` for none. A default would be Ruby
    culture overriding fidelity.
17. **The native layer refuses another platform's settings.** The private
    methods take every builder setting on every platform, and a setting the
    platform's arboard lacks raises `ArgumentError` instead of being
    ignored. The Ruby builders never send one; the check keeps a direct call
    honest.

18. **The gate fails on any rustc, Clippy, or Cargo warning.** Build
    steps exit zero with warnings, and `clippy -D warnings` misses some: an
    unknown lint in a `[lints]` table reaches rustc as a command-line flag,
    and `unknown_lints` ignores `-D warnings`. That let a misplaced
    `unsafe_code` entry (read as `clippy::unsafe_code`, so unsafe code was
    not denied at all) print `warning[E0602]` in a passing gate.
    `tasks/cargo_output.rb` runs each cargo step, and the extension compile
    in a child rake (`compile:strict`, the gate's first step), and fails on
    any line that starts a warning. Cargo replays a crate's warnings on a
    cached build, so later no-op compiles cannot hide one.
19. **RatatuiRuby's Rust configuration, adopted where it fits.** From
    RatatuiRuby's crate:
    - `clippy::undocumented_unsafe_blocks`, denied, so every `unsafe` block
      has its `SAFETY` comment.
    - `clippy.toml`'s `disallowed-methods` for `Box::leak` and `Vec::leak`,
      reworded for a binding: Ruby's garbage collector owns what the
      extension keeps. The file moves into the crate, so it ships in the
      gem and applies to it alone; the empty root one is gone.
    - `[profile.release]` with `debug = true` and `strip = false`, so a
      backtrace from an installed gem names its functions. It sits at the
      gem's workspace root, the only place Cargo reads profiles.
    - `cargo fmt --all --check`, and a `rust:clippy:fix` task for Clippy's
      automatic fixes.

    Skipped: the `.cargo/config.toml` macOS `-undefined dynamic_lookup`
    flags, because rb-sys's build script already passes them to every
    build, test, and Clippy run; the musl `crt-static` flag and the
    `staticlib` crate type on musl, because no musl machine or CI can test
    them here and Cargo reads `.cargo/config.toml` from the working
    directory, which an installing gem does not control (a follow-up with
    Alpine CI); the pedantic allows (`missing_errors_doc` and others),
    because Ferro's crate passes without them; the CI matrix and
    `BINDGEN_EXTRA_CLANG_ARGS`, because Ferro has no CI yet (a follow-up).
    No new tool was needed: RatatuiRuby uses none beyond Cargo, Clippy,
    and rustfmt.

### Tests

Tests run against the real crate and the real system clipboard. The helper
saves the clipboard's text before the suite and restores it after. Ported
from arboard's `src/lib.rs:282-516`: text round trip and persistence after
the clipboard is dropped, UTF-8 text, clear and clear twice, HTML without
and with alternative text, `get.html` (with the macOS wrapper,
`src/platform/osx.rs:316-318`), file lists, images (each format overwrites
the other; 2x2 and 3x2 round trips), the Linux selections and `wait`
(skipped off Linux), many clipboards at once, and `Send`/`Sync` as Ractor
shareability. Ferro's own: the image guard for each refused shape, each
error class and message, the platform surface on this platform, macOS's
`exclude_from_history` (read back with `osascript`), file-list failures,
argument types, encoding, and the gemspec's arboard version against
`Cargo.lock`. Rust unit tests cover the image check, panic capture, and
the deadline conversion, which Ruby cannot reach. The tooling tests are
Tokra's, adapted, plus tests for `pins:check` and the release task's
checks.

At least three manual mutation checks are run and recorded below.

### Unverified here

This machine is macOS, so the Linux and Windows paths never ran. rb-sys
refuses to cross-compile against a host Ruby, so the real crate could not
be checked for those targets. Instead, the Linux and Windows `platform`
modules were copied into a scratch crate with stand-ins for the five
magnus items they use and checked with `cargo check --target
x86_64-unknown-linux-gnu` and `--target x86_64-pc-windows-msvc` against
arboard 3.7.0: both compiled, so every arboard call and trait import they
make is right for its target. Their Ruby behavior (selections, `wait`,
the deadline conversion's Ruby side, the Windows exclusions) is
UNVERIFIED; `test_linux.rb` and `test_windows.rb` hold the tests a Linux
or Windows run would execute. CI on those platforms is a follow-up.

What the session found beyond the plan:

- arboard 3.7.0 still panics on macOS for an image with no bytes:
  `CGDataProviderCreateWithData` returns null and `src/platform/osx.rs:69`
  unwraps it. With the image guard removed, the panic guard caught it and
  raised `Ferro::Arboard::Error` ("arboard panicked: called
  `Option::unwrap()` on a `None` value"), so both guards are needed.

  permitted)` to stderr when a process outside the App Sandbox reads file

  Rust, and appears during the file-list tests.

  unpacked gem, needs every platform's dependencies in Cargo's cache, so
  `package:check` now runs `cargo fetch --locked` first.
- `gem build` warned about a duplicated URI; the packaging check now fails
