# Plan 011: A completeness audit, and the road to 1.0

Ferro has published nothing to RubyGems.org. Before the first push, the
maintainer asked whether each gem is a complete binding, with no deviation
from its crate that is not impossible to avoid. This plan records what a
first audit found, the decisions it needs, and the order of the work that
follows, so the findings outlive the session that produced them.

## Status

Open. The findings below come from one read-only inventory per gem, made
on 2026-11-04 by a Sonnet agent from the crate source that each gem's
`Cargo.lock` pins, before it read the gem's plan. Nothing was built or run,
and no finding has been checked. Each is a candidate until an Opus
reviewer rules on it against the crate source (step 2 below).

Steps 2 and 3 are done, except where a fix waits on a decision. On
2026-11-05 an Opus reviewer per gem ruled on every inventory row and
every bullet below, from the crate source, and each ruling that needed no
decision was fixed, reviewed again, and landed: global-hotkey 1e6a846,
rfd a67750b, url cb5c731, notify-rust 0017a4a, time 0c35d46, arboard
cc82825; idna needed no code change. Many inventory claims were false,
and the reviewers found defects the inventory missed. The bullets below
are the audit as written; read each gem's CHANGELOG and plan for what is
true now. In short:

- **Corrected here.** idna's `AsciiDenyList` lacks `Hash` in Rust, so no
  `eql?` or `hash` is owed. arboard's `file_list` is lossless on Linux and
  macOS, and its size guard is needed on Linux and Windows too.
  global-hotkey's raising handler ends delivery more gently than the
  crate does. url's `Host::to_owned` and `From<idna::Errors>` are forced.
  time's Integer arithmetic outside `i32` is faithful, since the crate's
  `u32` impl reinterprets the bits. notify-rust's error classes must come
  from its `Debug` text, since its `kind` is private.
- **Fixed defects the audit missed.** global-hotkey let `StopIteration`
  end delivery silently; rfd treated a parent with no window as attached
  on macOS; url let a frozen `Url` change through private methods and
  read a `Url` twice in `socket_addrs`; notify-rust let a frozen
  `Notification` be reset.
- **Waiting on the maintainer.** The six decisions below. Whether hidden
  and deprecated items are part of a gem's API (time). time's `ext`
  traits as refinements. Whether an rfd parent may answer "no handle"
  only with `nil`. notify-rust's `MacOsError` split. One name, across the
  gems, for payload readers and for integer discriminants. One design for
  test hooks shipped in extensions (arboard, url). How each gem moves off
  its dotted prerelease (Versioning).
- **Decided since (2026-11-05).** ADR 001's amendment settles Debug
  (`debug` beside Ruby's `inspect`), consumed values (a block form, or
  `IOError` on reuse), iterators (Enumerators), durations (Numeric seconds
  in, Rational out), hidden and deprecated items (unbound unless Tauri
  needs them), and errors the gems raise themselves. A second amendment of
  that day settles tuple variants, integer values, test hooks (a
  `test-hooks` Cargo feature that only the repository's own build turns
  on), and extension traits. ADR 002 settles Cargo features. First public versions are plain 0.x (see Versioning).
- **Done since.** No gem runs blocking work with the GVL held any more:
  arboard 57f2a76, rfd 00ed260, notify-rust 2a4eeae, url 3dc9f48,
  global-hotkey eba641f. ADR 001's rulings are applied to idna 04652e7,
  url 052233f, arboard 90d55e4, rfd e6dd7cc, notify-rust (plan 003,
  Follow-up: ADR 001's rulings), and time (plan 007, Follow-up: ADR 001's
  rulings), which binds std's `Duration` and time's `ext` traits as
  refinements. global-hotkey applies them, and is the first gem to adopt
  the test-hook design (plan 004, Follow-up: ADR 001's rulings; the
  bind-crate skill, section 4). arboard, url, and notify-rust follow it,
  so all four gems with test hooks build them only in the repository
  (plans 001, 005, and 003, Follow-up: test hooks).
- **Still to do.** For time, the four its plan 007 Follow-up leaves
  (errors' `debug`, consumed iterators, unbinding the deprecated items,
  positional format items); ADR 002's install-time options (rfd's gtk3,
  time's large-dates); the README rewrites (step 4); then plain 0.x bumps
  and tags.

## What the audit found

Coverage is broad. Each plan's table enumerates its crate's whole public
API, and the inventories agree that almost every item has a Ruby
counterpart: ferro-time alone has about 560 items, and nearly all are
bound. ferro-idna is essentially complete. No `unsafe` block lacks its
`// SAFETY:` comment, and no Ruby-reachable input was found that can panic a
crate outside `catch_unwind`.

The deviations are not yet all forced. They fall into three groups.

### Decisions that span every gem

Six questions recur across gems. Each needs one ruling, recorded as an
amendment to ADR 001, before the gems can be made consistent:

1. **Debug and `inspect`.** Rust's derived `Debug` prints a variant's bare
   name (`Passthrough`); the gems' `inspect` prints the constant path
   (idna, rfd, url's `Host`, arboard's `Error`). Some types derive `Debug`
   in Rust and have no `inspect` at all (notify-rust's handles, url's
   `UrlQuery` and `PathSegmentsMut`).
2. **Drop and consuming methods.** Where Rust acts when a guard drops, or a
   method consumes `self`, the gems apply each call at once or leave the
   value usable (url's `query_pairs_mut` and `path_segments_mut`,
   notify-rust's Linux handle after `wait_for_action` or `close`, url's
   `into_string`).
3. **Iterators.** Rust iterators become Arrays or Enumerators (url's
   `query_pairs`, `FormUrlencoded.parse`, and `byte_serialize`;
   global-hotkey's `Modifiers#iter`), and time's `Iter#next` answers `nil`.
   global-hotkey's receiver has no `each`, though plan 004 row 15 calls
   `IntoIterator` translated.
4. **Cargo features.** AGENTS.md says every Cargo feature is on, but about
   fifteen are off, each with a reason in its plan: rfd's `gtk3` and
   `common-controls-v6`; notify-rust's `d`, `d_vendored`, `z-with-tokio`,
   `tokio`, `env_logger`, `debug_namespace`, and `preview-macos-un`; time's
   `large-dates`, `rand` features, `quickcheck`, `wasm-bindgen`, and
   `serde-well-known`. Plan 007 row 81 says `serde-well-known` is built;
   the gem's `Cargo.toml` does not enable it. Either the rule gains an
   exception with a stated reason, or the features go on.
5. **Errors the gem makes.** arboard raises the crate's `ClipboardOccupied`
   for contention on its own lock. Several gems refuse inputs a crate
   would panic on by re-checking the crate's panic condition in the gem,
   which can drift from the crate as it changes.
6. **std's `Duration`.** time defers every operation that takes it, and
   notify-rust defers `From<Duration> for Timeout`, pending the repository
   decision plan 010 names.

### Gaps that look avoidable

- **global-hotkey:**
  - crossbeam's `TryRecvError#is_empty` and `#is_disconnected`,
    `RecvTimeoutError#is_timeout` and `#is_disconnected`, and the
    `From<RecvError>` conversions are unbound, with no plan row.
  - The error variants that carry a String or a `HotKey` expose it only in
    the message, and `OsError` drops its `io::Error`.
  - The RBS declares `Modifiers::FLAGS` and `ALL_BITS` public, but the code
    makes them `private_constant`.
  - A `set_event_handler` block that raises ends its thread, and every
    later event is dropped.
- **notify-rust:**
  - The gem chooses an error's class by parsing the crate's `Debug` text,
    because the crate's `kind` is private.
  - `timeout=` and `timeout(x)` accept different types.
  - `TryFrom` the image crate's types into `Image` is unbound.
- **arboard:**
  - `file_list` converts each `PathBuf` with `to_string_lossy`, so a path
    that is not UTF-8 changes.
  - `set_image` refuses an empty or mis-sized image on every platform,
    though only macOS panics on one.
  - A test hook, `native_gvl_releases`, ships in the extension.
- **idna:** `AsciiDenyList` is `Eq` in Rust but has no `eql?` or `hash`.
- **url:** `Host::to_owned` and `From<idna::Errors> for ParseError` are
  unbound, and `Position` gains a `Comparable` the crate lacks.
- **time:** `SignedDuration` multiplied or divided by an Integer outside
  `i32` raises `RangeError`, though the crate has `u32` impls. (False, as
  the corrections above say: the `u32` impls reinterpret the bits as
  `i32`, so no impl multiplies by an integer outside it; plan 007,
  Follow-up.)
- **rfd:** the Custom button variants name fields that Rust leaves
  positional.

### Deviations that look forced

These still need a ruling, but each has a reason in Ruby or in soundness:

- rfd's `set_parent` takes any object answering `window_handle` and
  `display_handle`; AppKit parents are window numbers (plan 008); Wayland
  handles are unbound, because rfd dereferences their raw pointers.
- Panics the crate would raise become Ruby exceptions in idna, url, time,
  and rfd, as AGENTS.md requires.
- Conversions that exist only for Rust's ownership are unbound: arboard's
  `into_owned_bytes` and `to_owned_img`, url's `Parse::into_owned` and its
  serde internals, and time's macros, `ext` traits, `__*_unchecked`
  constructors, and uninhabited variants.
- wasm32 items (rfd) and Windows' `debugger_visualizer` (url) have no Ruby
  target.

- **Tests.** About twenty items are bound with no test against the real
  crate:
  - idna: `SinkError`.
  - arboard: `wait_once`, `ClipboardNotSupported`, and `Unknown`.
  - global-hotkey: event delivery on macOS, the receiver's `dup`, `clone`,
    and `inspect`, and `FailedToWatchMediaKeyEvent`.
  - rfd: the message dialogs' `set_parent`, the async message setters, and
    `FileHandle#inner`.
  - notify-rust: `schedule_raw`, `UnableToSchedule`, `UnableToDeliver`,
    and the `Reply` response.
  - url: `is_special`, `has_host`, `UrlQuery`, and
    `PathSegmentsMut#clear`.
- **Plans.** Several plan tables have drifted from their code:
  - Plan 002 still lists the AppKit `ns_view` handle as deferred, though
    plan 008 bound it.
  - Plan 005 claims `Debug` on `UrlQuery` and `PathSegmentsMut`.
  - Plan 006 has no row for `Idna: Default`.
  - Plan 007's table predates plans 009 and 010, and its row 21 lists
    multiplication impls the gem does not bind. (Row 21 now names which
    impls have a Ruby operator; rows 13, 22, 36, 54, 75, 78, and 81 say
    what the Follow-up binds and ADR 002 drops.)
  - Line citations are off by a few lines in several.
- **READMEs.** Each README.rdoc becomes the gem's RubyGems description,
  frozen into each version:
  - Three give the wrong version for their own gem (arboard, notify-rust,
    rfd), and global-hotkey's names a Rust floor of 1.80.
  - Three say the gem "adds nothing of its own" though it does
    (global-hotkey, notify-rust, url), and arboard's "Three things differ"

  - time's says each std `Duration` operation has a bound `SignedDuration`
    twin, which is false for `unsigned_abs`, `TryFrom`, and the

  - Each says `bundle add` without a version and "needs no system
    libraries", though every gem needs libclang to build.

## Versioning

A SemVer prerelease (a hyphen, `1.6.0-beta.1`) is an opt-in preview of a
coming release, not a step between release lines. Bundler considers a
prerelease only for a user whose Gemfile or lockfile names one (bundler
4.0.4, `lib/bundler/resolver/package.rb:26`), so a user on stable 1.5.2
never gets 1.6.0-beta.1. A user who opted into the beta moves to 1.6.0
when it ships, because Bundler prefers the highest version and 1.6.0 sorts
above 1.6.0-beta.1.

The first public versions are therefore plain SemVer 0.x releases, such as
0.1.0, with no label. SemVer treats major version zero as unstable (item
4), and the number says so. Each gem's next release can be plain 0.1.0,
which sorts above all of its dotted 0.1.0.pre.N tags, so no old tag is
deleted. RatatuiRuby stranded its users by using 1.0.0-rc.1 as the upgrade
path from 0.9.0: a user on stable 0.9.0 is never offered a prerelease.
That misused the hyphen. It is no reason to label every 0.x.

Versions are written as SemVer (`1.0.0-beta.1`) in `version.rb`, in tags,
and in CHANGELOG headings. RubyGems stores that version as
`1.0.0.pre.beta.1`. `rake bump` and `rake release` now take the version
from `gem.spec.version`, the RubyGems form, so they would tag
`ferro-url/v1.0.0.pre.beta.1`. RatatuiRuby already reconciles the two
forms: `tasks/bump/sem_ver.rb`, `tasks/release.rake` lines 13 to 31, and
`tasks/release/native_gem_version.rb` in that repository. Its
`tasks/bump/release_branch.rb` is the release-branch policy that this
repository's bump task requires before any 1.0 (plan 001).

A README gives a plain Gemfile line for a stable release. For an opt-in
beta it gives the exact line, such as `gem "ferro-url", "1.6.0-beta.1"`,
and says that moving to the release is `bundle update`.

## Steps

1. The maintainer rules on the six repository-wide decisions, recorded as
   an amendment to ADR 001.
2. An Opus reviewer per gem checks the avoidable and forced rows above
   against the crate source, with the per-gem inventories as its starting
   list, and spot-checks that the inventories missed nothing that a macro
   or a trait generates.
3. The fixes, the missing tests, and the plan corrections, gem by gem, with
   a CHANGELOG entry for each change users can observe.
4. Each README is rewritten in full, then the gem is bumped to
   its plain 0.x release and tagged.
5. Port RatatuiRuby's version tooling and release-branch policy, and add a
   release task that pushes an already-tagged version (`rake release:<gem>`
   refuses once the tag exists). Add the prerelease rule to AGENTS.md: a
   prerelease is an opt-in preview, and the first versions are plain 0.x.
6. The maintainer publishes to RubyGems.org (Tokra plan 059 gives the
   order).
7. Each gem reaches 1.0.0 once step 2 finds nothing avoidable left and
   Tokra's plugins have used it. A beta or release candidate comes first
   only when users should preview the release, and is opt-in.
   Readiness differs: idna first; then arboard, rfd, and url;
   global-hotkey and notify-rust have the most to do; time, whose std
   `Duration` decision is now applied, has the four items plan 007's
   Follow-up leaves.
