= ferro-time

{rdoc-image:https://justin.searls.co/img/shovelware.svg}[https://justin.searls.co/shovelware/]

Dates, times, offsets, and durations for Ruby, through time 0.3.55.

Ruby's ::Time and ::Date answer most date questions, by Ruby's rules. A
program that exchanges dates with a Rust service, or must agree with
Tauri, needs the Rust side's rules instead: which ISO 8601 and RFC 3339
strings parse, how RFC 2822 writes a date, how far a date may range, and
the words an error uses. Getting those right by hand means porting a
parser step for step and keeping the port current.

ferro-time binds time (https://github.com/time-rs/time), Rust's date and
time library, one to one. It keeps time's names and behavior and adds
nothing of its own. Use it to parse a date the way a Rust program will,
format one it will read back, or do calendar arithmetic with time's
answers.

== Install

--
SPDX-SnippetBegin
SPDX-SnippetCopyrightText: 2026 Kerrick Long <me@kerricklong.com>
SPDX-License-Identifier: MIT-0
++

  bundle add ferro-time

--
SPDX-SnippetEnd
++

The gem compiles a Rust extension when it installs, so the machine that
installs it needs Rust and Cargo: Rust 1.88 or newer, and 1.99 or newer on
macOS 27, where earlier toolchains strip the extension in a way the new
loader rejects. The build runs <tt>cargo --locked</tt>, so it compiles
exactly the dependency versions this gem was tested with. To build against
newer ones anyway, set +RB_SYS_EXTRA_CARGO_ARGS+ (an empty string will
do); it replaces <tt>--locked</tt>. Building needs no system libraries.

== Use

--
SPDX-SnippetBegin
SPDX-SnippetCopyrightText: 2026 Kerrick Long <me@kerricklong.com>
SPDX-License-Identifier: MIT-0
++

  require "ferro/time"

  t = Ferro::Time
  well_known = t::FormatDescription::WellKnown

  # Parse an instant as time's ISO 8601 parser reads it:
  at = t::OffsetDateTime.parse("2026-10-26T12:00:00.000Z", well_known::Iso8601::DEFAULT)
  at.unix_timestamp # => 1_793_016_000

  # Move it, and write it back:
  later = (at + t::Duration.hours(36)).to_offset(t::UtcOffset.from_hms(9, 0, 0))
  later.format(well_known::Rfc3339) # => "2026-10-28T09:00:00+09:00"

  # Describe your own format, checked once and used as often as you like:
  day = t::FormatDescription.parse_owned(3, "[weekday], [month repr:long] [day padding:none]")
  later.format(day) # => "Wednesday, October 28"

  # time's errors, as classes:
  t::Date.from_calendar_date(2026, t::Month::February, 29)
  # raises Ferro::Time::Error::ComponentRange: day was not in range

--
SPDX-SnippetEnd
++

Every error time raises is a Ferro::Time::Error, with a class for each of
time's error types and variants nested as Rust nests them, so <tt>rescue
Ferro::Time::Error::Parse</tt> catches any failed parse. Every message is
time's own.

== Ferro::Time, Ruby's Time, and Ruby's Date

Ferro::Time::Time and Ferro::Time::Date are time's types, not Ruby's
::Time and ::Date. The names are time's, and the module keeps them apart,
with one consequence: wherever ferro-time is loaded, a bare +Time+ inside
<tt>module Ferro</tt> names Ferro::Time, because Ruby looks a constant up
lexically first. Code in the Ferro namespace writes <tt>::Time</tt> and
<tt>::Date</tt> for Ruby's own.

OffsetDateTime, UtcDateTime, and Timestamp convert to and from Ruby's
::Time, which stands for Rust's +SystemTime+: OffsetDateTime.from(time),
#to_time (a UTC ::Time), and <tt>==</tt>, <tt><=></tt>, and <tt>-</tt> with a ::Time on the
right, as time's +SystemTime+ impls do. Ruby's own ::Time is not
changed; its <tt><=></tt> already asks the other value when that value is
not a ::Time, so <tt>time == offset_date_time</tt> and
<tt>time < offset_date_time</tt> work as well, while <tt>time - offset_date_time</tt>
stays Ruby's +TypeError+. Timestamp converts to and from UtcDateTime and
OffsetDateTime as well, and compares and subtracts with both. Nothing converts to or from Ruby's ::Date,
because time has no conversion for it.

== How it maps time

The API is time's, translated where Rust has no Ruby meaning:

* Rust's modules are Ruby modules: <tt>time::format_description::well_known::Rfc3339</tt>
  is Ferro::Time::FormatDescription::WellKnown::Rfc3339. The aliases
  +PrimitiveDateTime+ and +Duration+ are the same classes as PlainDateTime
  and SignedDuration.
* +Result+ raises; +Option+ is +nil+; tuples are Arrays; Month and Weekday
  are frozen constants.
* Every value is frozen and immutable, as Rust's +Copy+ values are, and
  compares, orders, and hashes as time's +PartialEq+, +Ord+, and +Hash+ do.
* Rust's operators are Ruby's: <tt>date + duration</tt>,
  <tt>datetime - other</tt>, <tt>duration * 3</tt>, <tt>-offset</tt>.
  Multiplying uses time's <tt>i32</tt> impl, Rust's type for an integer
  literal, from either side: <tt>2 * duration</tt> reaches time's
  reflexive impl through SignedDuration#coerce, and no other operator
  takes a number on the left, as in Rust.
* A description is a FormatDescriptionV3, the classes Rfc2822 and
  Rfc3339, an Iso8601 with any Config, or format items: a
  BorrowedFormatItem, an OwnedFormatItem, or an Array of either, as
  FormatDescription.parse_borrowed and parse_owned return for versions 1
  and 2, and parse_strftime_borrowed and parse_strftime_owned for
  +strftime+. +format_into+ appends to a String.
* Format items, components, and modifiers are frozen +Data+ values you
  can read and build: <tt>Component::Day.new(Modifier::Day.default)</tt>.
  A modifier comes only from its +default+ (or Modifier::Ignore.count)
  and its +with_+ builders, as in Rust. Naming a type or variant time
  deprecates warns in Ruby's +:deprecated+ category.
* A Timestamp counts seconds and nanoseconds from the epoch, with the
  nanoseconds always forward: <tt>Timestamp.new(-1, 500_000_000)</tt> is
  half a second before the epoch. #replace_millisecond,
  #replace_microsecond, and #replace_nanosecond differ from
  UtcDateTime's only on an instant before the epoch that has a fraction:
  there they replace the fraction as its decimal text writes it, so
  replacing the 500 ms of -0.5 with 400 gives -0.4, where a clock would
  give -0.6. A whole negative second is not special:
  <tt>Timestamp.new(-1, 0).replace_millisecond(400)</tt> is -0.6, as time
  does.
* Parsing::Parsed is time's parser state: mutable, with time's getters,
  setters (+true+ or +nil+), and +with_+ builders. Each date and time type
  has +try_from+ a Parsed and +parse_with_defaults+.
* The iterators of Iter are time's, not Ruby's Enumerator:
  <tt>date.iter_to(end_date)</tt>, Month.iter_from, and Weekday.iter_from
  make them, and +next+ advances one in place and returns +nil+ once a
  DateIter is done, never +StopIteration+. Each includes Enumerable, whose
  methods walk a copy and leave the iterator where it was. time's own
  methods keep their names (+next_back+, +nth+, +len+, +size_hint+,
  +all+, +any+, +is_sorted+); +count+ and +last+ on a never-ending month
  or weekday iterator raise +RangeError+ where Rust panics.
* The units of time are frozen values: <tt>Unit::Nanosecond.per(Unit::Second)</tt>
  is 1_000_000_000, and <tt>per_t(Float, ...)</tt> takes the output type
  first, Integer or Float. Rust's const +N+ on each unit is 1 here, the
  only value +per+ exists for. The deprecated +Convert+ is the same
  module, and naming it warns.
* time's macros check their input when Rust compiles; their run-time
  equivalents are bound. <tt>date!(2020-01-02)</tt> is
  <tt>Date.from_calendar_date(2020, Month::January, 2)</tt>; +time!+,
  +offset!+, +datetime!+, and +utc_datetime!+ are Time.from_hms,
  UtcOffset.from_hms, PlainDateTime.new with #assume_offset, and
  UtcDateTime.new; <tt>timestamp!</tt> is Timestamp.new, or Timestamp.from
  a UtcDateTime; and <tt>format_description!(version = 3, "...")</tt> is
  <tt>FormatDescription.parse_owned(3, "...")</tt>, while the macro's
  default version 1 is <tt>FormatDescription.parse_borrowed(1, "...")</tt>.

What differs from calling time from Rust:

* time panics on arithmetic that leaves its range, on a NaN or
  overflowing float, and on integer division by zero. The gem checks the
  same conditions first and raises +RangeError+ with time's message, or
  +ZeroDivisionError+, instead. Any other panic raises Ferro::Time::Error
  with <tt>time panicked: ...</tt> rather than ending your Ruby process.
* Formatting a type with a well-known format that needs more than the type
  holds, such as RFC 3339 for a Date, is a compile-time error in Rust. The
  gem raises +TypeError+ with time's assertion.
* A borrowed format item holds its own frozen copy in Ruby, so it differs
  from an owned one only by class; time never compares the two, and
  neither does the gem. A tree of items nested more than 255 levels deep,
  deeper than time's own parser goes, raises +ArgumentError+ rather than
  risk overflowing the native stack.
* Each ISO 8601 configuration is its own compiled type in Rust. The gem
  formats any configuration by formatting the date, time, and offset parts
  with time's formatters and joining them as time does; a test checks the
  result against time's own formatter.

Not bound yet: every impl with std's unsigned +Duration+ (Timestamp's
included), whose Ruby value is a choice for all of Ferro's gems at once,
and SignedDuration's +Display+ with a precision, which waits with the
width and fill of every type's +Display+ for one translation of Rust's
formatter. Each operation with std's +Duration+ has a SignedDuration twin
that is bound. ferro-time's plan 010 says why for each. time's +serde+ and +macros+ features are built and add no Ruby API.

time's +large-dates+ feature is off, as Tauri and its plugins build time,
so years run from -9999 to 9999. The +rand+, +quickcheck+, and
+wasm-bindgen+ features are off: they serve Rust callers only.

The local offset (UtcOffset.current_local_offset,
OffsetDateTime.now_local) comes from the system's time-zone rules and is
safe in a multi-threaded process, as time guarantees. Util.refresh_tz
refreshes those rules only where time can prove the call sound: on macOS
it runs, and on Linux, where a Ruby process is never single-threaded, it
returns +nil+.

The extension is Ractor-safe, and every value the gem makes is frozen and
shareable. On Windows, Ruby 4.0.9 can hang when a Ractor starts a garbage
collection while the main Ractor has another thread asleep; the bug is
Ruby's (ferro-arboard's README says more).

ferro-time binds time 0.3.55. The gem's version follows its
own API; its +time_version+ metadata names the time release.
