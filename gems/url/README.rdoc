= ferro-url

{rdoc-image:https://justin.searls.co/img/shovelware.svg}[https://justin.searls.co/shovelware/]

URLs the way browsers read them, for Ruby, through url 2.5.8.

Browsers parse URLs by the WHATWG URL Standard. Ruby's +URI+ follows RFC
3986, an older grammar, so the two disagree about strings people type
every day: a backslash for a slash, a missing pair of slashes, a host in
Unicode, a port of 99999. A Ruby program that must agree with a browser,
or with a Tauri app, gets different answers from +URI+.

ferro-url binds url (https://github.com/servo/rust-url), the crate Servo,
Firefox's Rust code, and Tauri use, one to one. It keeps url's names and
behavior, and its form_urlencoded module. Where Rust has no Ruby meaning
it translates: the one class it adds is Ferro::Url::Error, which stands in
for url's <tt>Result<_, ()></tt> failures and carries a panic it caught.
Use it to validate a link the way a webview will follow it, resolve relative
references against a page, change a URL's parts with a browser's setters,
or read and write query strings.

ferro-url binds url 2.5.8 and form_urlencoded 1.2.2. The gem's version
follows its own API; its +url_version+ metadata names the url release.

== Install

Add the gem to your Gemfile, with a version, or let Bundler write the line:

--
SPDX-SnippetBegin
SPDX-SnippetCopyrightText: 2026 Kerrick Long <me@kerricklong.com>
SPDX-License-Identifier: MIT-0
++

  gem "ferro-url", "~> 0.1"

  # or, from the command line:
  bundle add ferro-url --version "~> 0.1"

--
SPDX-SnippetEnd
++

The gem needs Ruby 4.0 or newer. It compiles a Rust extension when it
installs, so the machine that installs it needs:

* Rust and Cargo, 1.88 or newer (the highest +rust-version+ among the
  locked dependencies). On Windows, use Rust's +x86_64-pc-windows-gnu+
  toolchain, since RubyInstaller's Ruby is a MinGW build and rb-sys
  refuses to build it with the MSVC target.
* libclang, which rb-sys's bindgen reads Ruby's headers with
  (<tt>libclang-dev</tt> on Debian and Ubuntu, +clang+ with the Xcode
  command line tools on macOS, LLVM on Windows).

The build runs <tt>cargo --locked</tt>, so it compiles exactly the
dependency versions this gem was tested with. To build against newer ones
anyway, set +RB_SYS_EXTRA_CARGO_ARGS+ (an empty string will do); it
replaces <tt>--locked</tt>. url's Unicode data comes from ICU4X through
idna and is compiled in, so url links no system library, at build time or
run time.

== Use

--
SPDX-SnippetBegin
SPDX-SnippetCopyrightText: 2013-2025 The rust-url developers
SPDX-License-Identifier: MIT OR Apache-2.0
SPDX-SnippetComment: Translated from url 2.5.8 src/lib.rs:32 and :93-111
++

  require "ferro/url"

  url = Ferro::Url::Url.parse("https://github.com/rust-lang/rust/issues?labels=E-easy&state=open")
  url.scheme               # => "https"
  url.host_str             # => "github.com"
  url.path_segments.to_a   # => ["rust-lang", "rust", "issues"]
  url.query_pairs.to_a     # => [["labels", "E-easy"], ["state", "open"]]

  Ferro::Url::Url.parse("../main.css")
  # raises Ferro::Url::ParseError::RelativeUrlWithoutBase: relative URL without a base

  page = Ferro::Url::Url.parse("http://servo.github.io/rust-url/url/index.html")
  page.join("../main.css").as_str # => "http://servo.github.io/rust-url/main.css"

  url.set_query(nil)
  url.query_pairs_mut.append_pair("q", "café & crème")
  url.as_str # => "https://github.com/rust-lang/rust/issues?q=caf%C3%A9+%26+cr%C3%A8me"

--
SPDX-SnippetEnd
++

A string that is not a URL raises a subclass of Ferro::Url::ParseError
with url's message, the text a Tauri app reports. The setters url answers
only yes or no for, such as +set_port+ on a <tt>mailto:</tt> URL, raise
Ferro::Url::Error instead of returning false.

Setters change the URL in place, like a browser's:

--
SPDX-SnippetBegin
SPDX-SnippetCopyrightText: 2026 Kerrick Long <me@kerricklong.com>
SPDX-License-Identifier: MIT-0
++

  url = Ferro::Url::Url.parse("https://example.com/a/b")
  url.path_segments_mut { |segments| segments.pop.push("c d") }
  url.set_host("example.org")
  url.as_str # => "https://example.org/a/c%20d"

  Ferro::Url::Url.parse("mailto:me@example.com").set_port(80)
  # raises Ferro::Url::Error: url::Url::set_port returned Err(())

  Ferro::Url::Url.parse("http://example.com:99999")
  # raises Ferro::Url::ParseError::InvalidPort: invalid port number

--
SPDX-SnippetEnd
++

== How it maps url

The API is url's, translated where Rust has no Ruby meaning:

* <tt>url::Url</tt> is Ferro::Url::Url, beside url's other root items:
  Host, Origin, OpaqueOrigin, ParseError, SyntaxViolation, Position,
  ParseOptions, PathSegmentsMut, UrlQuery. url re-exports the
  form_urlencoded crate, which is Ferro::Url::FormUrlencoded.
* A Url changes in place, as in Rust. +dup+ copies it, a frozen Url
  refuses every setter, and URLs compare and hash by their serialization.
  +debug+ is url's +Debug+ text, and +inspect+ is Ruby's.
* Host's and Origin's variants are Data classes; addresses are IPAddr, and
  socket_addrs returns an Array of Addrinfo.
* <tt>url[Position::BeforePath..]</tt> slices as url's +Index+ impls do,
  with Ruby ranges of Position.
* ParseOptions is a frozen value whose setters return a new one, as
  Rust's +Copy+ value does. Its callbacks, and a Serializer's encoding
  override, are any callables.
* +path_segments_mut+ and +query_pairs_mut+ return objects that change the
  URL with each call, where Rust's borrow the URL until dropped;
  +query_pairs_mut+ gives the URL its <tt>?</tt> at once, as url's does.
* +path_segments+ returns an Enumerator. +query_pairs+ and
  FormUrlencoded's +parse+ and +byte_serialize+ return form_urlencoded's
  iterators, with +next+, +each+, and Enumerable.

What differs from calling url from Rust:

* A <tt>Result<_, ()></tt> raises Ferro::Url::Error, which url does not
  have, with a message naming the function.
* Where Rust would panic, the gem raises instead, with Rust's message:
  +IOError+ for a Serializer used after +finish+, +RangeError+ for a slice
  that runs backward, +ArgumentError+ for a start position form_urlencoded
  cannot use. Any other panic
  inside url raises Error with <tt>url panicked: ...</tt> rather than
  ending your Ruby process, and a Url keeps its value from before the call.
* +socket_addrs+ resolves the host on a thread of its own and waits with
  Ruby's global VM lock released, so other threads run, and Ctrl-C,
  <tt>Thread#raise</tt>, and +Timeout+ end the wait at once; the lookup,
  which nothing can cancel, then finishes alone, as Ruby's own
  <tt>Addrinfo.getaddrinfo</tt> leaves its resolver thread. When no
  lookup thread can start, the lookup runs on the calling thread, still
  with the lock released. Every other call keeps the lock.
* Nothing of Ruby's runs while a Url's native lock is held, so threads and
  Ractors sharing one Url never wait on each other inside the VM.
* A Serializer calls its encoding override for each name and value before
  form_urlencoded runs, in form_urlencoded's order, rather than during.
* Not bound, each for a reason:
  * +serialize_internal+ and +deserialize_internal+ exist only for a serde
    caller, and the gem does not build serde.
  * The +quirks+ module and +check_invariants+ are hidden in url
    (<tt>#[doc(hidden)]</tt>), and Tauri uses neither.
  * +into_string+ is deprecated since url 2.3.0, in favor of <tt>Into<String></tt>;
    use Url#to_s. Tauri does not use it either.

url's +std+ feature (its default) is built. Three others are off. +serde+
reaches only Rust, since the string it writes is Url#as_str, which
Url.parse reads; ADR 002 drops it. +expose_internals+ adds only items to
the unbound +quirks+ module. +debugger_visualizer+ names a file the
published crate does not include, so it cannot build; it would add no Ruby
API.

url keeps one piece of process-wide state, the counter that numbers opaque
origins, and nothing the operating system holds, so another library in the
same process may link its own copy. url's host parser uses its own copy of
idna; ferro-idna binds idna directly and locks the same release.

The extension is Ractor-safe; Host, Origin, Position, SyntaxViolation, and
a frozen Url may cross Ractors. One caveat belongs to Ruby, not to the
gem: on Windows, Ruby 4.0.9's scheduler can hang when a Ractor starts a
garbage collection while the main Ractor has another thread asleep (in
+sleep+ or Queue#pop) and its main thread waits in Ractor#value. It needs
no URL, and Ruby 4.1 replaces the Windows scheduler involved.
ferro-arboard's README says more.
